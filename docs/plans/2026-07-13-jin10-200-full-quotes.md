# Jin10 200-Item Feeds And Full Quote Universe

## Goal

Expand the Jin10 page without exhausting the MCP per-tool daily quota:

- Keep the latest 200 market flashes.
- Keep the latest 200 news items.
- Show the latest 200 calendar events.
- Discover and display every quote code exposed by `quote://codes`.

## Data Flow

1. Initial load and manual full refresh request up to 10 pages for flash and news.
2. Background feed refresh requests only the first page, merges by stable identity, and keeps 200 rows.
3. Calendar remains a single MCP call and the frontend keeps the latest 200 rows.
4. Quote codes are discovered from the MCP resource instead of a hard-coded four-code list.
5. Quote requests are split into batches of 20, matching the backend batch limit.

## Refresh Policy

- Flash, news, and calendar: every 90 seconds.
- Core quotes (`XAUUSD`, `USOIL`, `USDCNH`, `USDJPY`): every 10 minutes.
- Full quote universe: every 4 hours.
- Manual full refresh: deep feeds plus all quote codes.

This keeps routine `get_quote` usage below the documented 1,500 calls per tool
per Beijing calendar day for the currently observed quote universe, while still
providing a complete page.

## Failure Behavior

- A failed refresh does not clear previously loaded rows.
- Partial quote failures retain successful rows and show the failed codes.
- The UI reports the current row count and latest successful refresh time.

## Verification

- Python tests cover backend multi-page dispatch and page-limit clamping.

  tiered polling.
- Vite production build validates the TypeScript/React integration.
- Browser verification checks all four tabs, row counts, scrolling, refresh,
