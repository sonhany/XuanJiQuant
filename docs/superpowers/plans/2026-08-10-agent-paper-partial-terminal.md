# Agent 模拟盘部分成交终态实施计划

日期：2026-08-10  
依据：`docs/superpowers/specs/2026-08-10-agent-paper-partial-terminal-design.md`

## 1. 失败测试先行

- 扩展订单路由测试，要求部分成交取消返回 `filled_qty/remaining_qty/cancelled_qty`。
- 增加 Agent 控制器端到端测试：部分成交后取消必须完成账本及工具回执，普通拒单不得进入未知态。
- 强化完成回执丢失测试：从持久化证据恢复且不重复执行。
- 增加历史部分成交严格修复测试和恢复晋级后首次模拟交易测试。

## 2. 前向执行闭环

- 在执行取消动作中持久化数量拆分和终态原因。
- 在订单路由摘要中保留数量拆分。
- 在模拟交易运行器发现非终态时显式关闭为未知，禁止正常返回却遗留 `running`。
- 协调器按订单、成交数量和取消审计验证四种终态，并把数量证据交给 Agent 工具回执。

## 3. 严格历史修复

- 新增只追加的部分成交剩余量修复入口。
- 校验完整执行身份链、会话关闭、fencing 前进、订单声明、成交数量和无后续歧义。
- 追加取消终态和完成回执；调度器只在未知模拟执行恢复路径调用该入口。
- 对不满足证明条件的运行保持关闭，不修改事实。

## 4. 状态与恢复基线

- 保证成功晋级清零恢复计数、重试时间和历史失败基线。
- API/UI 显示自治恢复原因及预计恢复时间，并严格区分恢复、影子和显式关闭。

## 5. 验证与交接

- 运行新增测试并记录 RED/GREEN 证据。
- 备份活动数据库后，修复当前严格匹配的卡住运行并复核账本、工具回执和恢复状态。
- 更新 `README.md` 与 `docs/XUANJI_HANDOFF.md` 的执行闭环关系。
- 运行相关 Python、全部 Node 契约、TypeScript、Vite、Web/UI、浏览器控制台和真实 API 检查。
