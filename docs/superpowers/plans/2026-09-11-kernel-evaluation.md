# 交易内核评估实施计划

依据：`docs/superpowers/specs/2026-09-11-market-reference-ai-paper-system-design.md`，用户批准五阶段路线。

目标：用隔离可重复实验比较LEAN与NautilusTrader，区分原生能力、A股扩展能力和未验证能力。评估不调用当前F5、不访问密钥、不写活动账户。

## 执行顺序

- [x] 获取并固定官方发行版本，记录本机运行条件。
- [x] 在`.venv-kernel-eval`及`data/kernel-evaluation`安装隔离依赖，不改变现有Python/Qlib或系统SDK。
- [x] 在`experiments/kernel_evaluation`保存统一场景、内核实验和自动断言。
- [x] 对报价驱动成交、部分成交、撤单、重复成交事件、现金和费用使用真实内核对象或回测引擎执行；比较证据深度见结果报告。
- [x] 明确同日买卖/T+1、涨跌停、停牌、资金冻结、公司行动等A股规则的原生缺口；未经实际测试不标记通过。
- [ ] 对事件重建/恢复测试与进程重启/持久恢复分别标记证据级别。
- [x] 输出环境版本、固定输入、结果、启动耗时和适配代价；选择Nautilus为开发主线，活动OMS准入仍待同粒度与持久恢复验证。

## 比较与验收规则

固定CNY现金100000元，测试证券600000，每手100股，报价精度0.01元。场景标记为工程合成数据，不充作真实行情或样本外策略绩效。

S01：1000股、10元买入的成交与账户余额。
S02：1000股订单分400/600成交，终态与持仓应合计1000。
S03：400股部分成交后取消，持仓400、剩余取消600。
S04：同一成交事件重复投递，核对是否重复记账或明确拒绝。
S05：超出现金的买单，区分内核拒绝、默认负余额许可和需扩展。
S06：同日买入后卖出，应按A股T+1策略拒绝；原生允许则记录缺口。
S07：涨跌停/停牌分别测试可配置限制，不能把一般限价单等同涨跌停规则。
S08：事件回放重建订单；另列重启和持久账户恢复，不能混淆。

上述场景以独立断言消费内核结果，不调用当前项目planner/simulator来替代候选引擎。未安装或缺运行证据的内核不记为失败，也不记为通过。只有具备相同级别证据后才能正式选择活动OMS。
