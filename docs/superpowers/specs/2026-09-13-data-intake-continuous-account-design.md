# 真实数据准入与单账户连续回放设计

范围：承接已批准的确定性模拟路线。先完成真实数据接口诊断和单账户跨批次延续，再进入 AI 影子；本轮不启用 AI、不接券商、不切换 F5。遵循用户“按推荐执行，不重复询问”要求。

## 已验证的问题

2026-09-13 本机 Web 与 `/api/data?action=stats` 返回 200。POST `/api/data` 的 `hot_snapshot` 对 600000 返回 sina 行情：采集时间 11:36:24，行情时间 15:34:59，已有 `quote_timestamp_future` 标记。页面用最新价并不足以向 Nautilus 提供真实可信的买一/卖一、可成交股数和日状态。不得用最新价伪造双边报价，也不得把本机采集时间替换为行情事件时间。

现有 `Journal.execute` 每个 ID 独立起算，只适合实验。本阶段禁止靠每天新建试验模拟资金/持仓延续。

## 方案比较与选择

1. 每批次独立运行再拼接结果：会重置资金、T+1 和费用基线，拒绝。
2. 单账户追加不可变输入，沿用已验证的完整重放内核，以最新结果作为唯一账户投影：本轮采用；可测、可恢复，成本随历史增长，不宣称低延迟热运行。
3. 原生长期运行引擎和增量快照恢复：是后续在线化目标；当前没有验收过原生增量恢复，不能直接上线。

## 模块边界

`trading_system/intake.py` 只消费固定本地数据 API 的 hot_snapshot，输出带原始输入哈希的准入报告。记录请求股票池、实际覆盖、来源、源时间、接收时间、本轮核验时间、每项阻断。HTTP 有超时、响应体与股票数上限，不调用更新、交易或后台调度接口。调用行情接口可能更新其既有报价缓存，不改变采集器控制权。

`trading_system/continuous.py` 在现有 Journal 上增加一个账户的追加契约，不另写撮合或现金公式。数据库仅允许一个 account_id，revision 从 1 递增。每批次保存 batch_id、原始块哈希、上一结果哈希和完整输入前缀。资金、币种、证券、成本、参与率等初始配置冻结；只接受严格向后追加的帧、新的未来交易日和不改写既有日期的目标。任何旧日期/旧目标改写拒绝。

`trading_system/cli.py` 增加 data-probe 与 account-append/account-status/account-recover。数据诊断不打开账户日志；账户操作要求独立的显式日志路径。旧 run/recover/status 保持不变。严禁自动将 data-probe 输出转订单。

## 准入规则

现有报价可以被观察但未必可执行。逐股票检查来源、事件时间语义、时间时区、新鲜度、未来时间、双边价格/数量、数量单位、证券身份和日状态（日期、停牌、版本、价格带）。股票池缺失或含未请求代码、未知状态、上游 stale 均不可通过。休市单独报告，不把旧价格称作实时。每个报价按本轮核验时间计算有符号时差，未来时间不截为零。

只有接口明确提供执行字段才能 `execution_ready=true`；此布尔值也不授予任何执行权限。当前来源未提供这些字段时报告真实缺口，本轮不假造补齐。接口适配器不读数据层私有表、不导入 quant 缓存模块。

## 连续账户与恢复规则

每次追加需 expected_revision 乐观并发检查；相同 batch_id/相同块内容返回原提交结果，不再次成交；相同 batch_id 改内容拒绝。相同文件仍受 Journal 进程锁保护。只允许一个待完成尾批次，未恢复前不能追加新批次。账户状态分别展示已提交 revision 和 pending revision，不能把 pending 当完成。

追加重放的历史成交前缀必须与上一结果完全相同，否则不提交为完成。最新投影包含累计成交，但下游不得把每一版累计成交相加。账户恢复按日志重建；同 ID 重复不会解锁当日可卖量，跨日卖出按原始买入批次判断 T+1。上限沿用 10000 帧，新增 100 个批次上限，触顶拒绝而非截断历史。

本轮采用全量回放，支持跨进程/跨批次延续，不支持无限后台运行、跨证券组合、公司行动或原生增量快照恢复。新日志留在 data/nautilus-baseline，活动 F5 文件绝不作为写入目标。

## 验收

真实 API 捕获一次证据，真实缺字段必须保持阻断。使用本地 HTTP 服务的完整夹具验证成功、超时/畸形响应和未知数据；用真实 Nautilus 和临时 SQLite 验证跨批次持仓/资金延续、同日卖出拒绝、跨日退出、重复/冲突、配置改变、倒序帧、错误账户、历史链篡改、强退后 pending 恢复。原有 34 项基线全量回归。

交付记录：测试数、真实来源与时间、覆盖率、阻断、完整重放耗时以及未验收范围。只有数据合约通过且连续账户证据完成后才能接下一阶段 AI 影子；影子只记录建议并做对照，无执行权限。
