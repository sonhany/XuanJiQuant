# AI 自主模拟量化架构规格

日期：2026-09-11。状态：架构草案；用户已选择“仅模拟自治”，本文件的详细接口与迁移尚未实施。

## 1. 产品目标与范围

系统在人工预先配置的股票池、策略候选和风险预算内，自主完成数据准备、策略比较、组合决策、模拟调仓、持仓监控、异常恢复与盘后研究。正常周期不需要逐笔人工批准。自主的验收对象是一个可追溯的决策与交易周期，而非模型调用次数或成交数量。

本阶段只做A股模拟：没有券商适配器、实盘凭据或实盘开关。历史F5账本继续保存；旧Agent实现不恢复。新的AI决策域使用现存模型连接能力，所有模型输出都受确定性契约验证。

“完整接管”定义：AI是常态组合决策的唯一提出者，可以选择或暂停许可策略、在批准的参数空间内分配权重、持有现金、生成再平衡目标、安排白名单研究任务并基于反馈调整下一次决策。计算器负责因子和策略信号数值，风控负责最终许可，执行器负责模拟成交。AI不承担算账、编造行情、写成交或自行修改规则的职责。

## 3. 路线选择

推荐渐进替换：先固定数据接口和唯一账本，再拆出策略注册与发布、新AI决策域、统一风控输出、独立告警。每次只切换一个入口。

另外两条路线的代价：整体重写会同时丢失现有数据和模拟结算经验；在现有F4/F5外面直接再套一个Agent会保留多状态、多入口问题。暂不引入微服务、Kafka、ClickHouse或额外数据库服务；性能证据需要时再单独评审。

## 4. 目标职责

| 模块 | 唯一职责 | 产物与消费者 | 不得拥有的权限 |
|---|---|---|---|
| 数据服务 | 按交易日历独立采集、补齐、校验、发布数据 | MarketSnapshot、PIT版本；供研究、策略、AI、风控 | 不做选股或授予交易许可 |
| 因子引擎 | 按版本公式计算特征、IC、覆盖与稳定性 | FeatureSnapshot、FactorEvaluation；供策略和研究 | 不直接形成订单 |
| 策略研究/F4/Qlib | 产生候选、样本外评估、成本/约束验证 | 不可变ResearchReport；供策略注册器 | 不直接修改活动组合或运行许可 |
| 策略注册与运行 | 发布许可策略包，按已验证计算方式产生信号 | StrategyRelease、SignalSet；供AI | 不读任意latest报告决定是否关停所有策略 |
| AI决策服务 | 解释市场证据，选择许可策略、分配预算、形成组合、复盘 | DecisionProposal；供组合构建器与verifier | 不执行任意代码，不自改风险阈值，不写账本 |
| 组合构建器 | 将决策和信号转换成可行目标与调仓差额 | TargetPortfolio、OrderIntent；供风控 | 不悄悄改变AI提出的股票范围/预算，调整必须回报 |
| 风控服务 | 统一组合许可、逐单检查、持仓风险事件 | RiskAssessment、RiskDecision；供执行和页面 | 不用LLM替代规则，不以告警条数循环计算风险 |
| F5执行与账本 | 账户单写者、模拟撮合、费用、T+1、结算、对账 | Order、Fill、AccountSnapshot；供AI/风控/界面 | 不挑选策略，不生成虚构成交 |
| 告警服务 | 订阅事实、去重、升级、恢复验证、投递 | AlertEvent、DeliveryReceipt；供操作员与AI | 不直接下单，不将确认/静音等同于风险解除 |
| 运行协调器 | 交易时钟、作业依赖、互斥、重试、检查点 | Cycle状态和任务事件 | 不输出投资意见 |
| Web/API | 呈现统一投影、发送受控请求 | 当前状态、解释、历史回放 | 不自算风险许可，不成为交易时钟 |

依赖顺序：数据与特征 → 策略信号 → AI组合提案 → 组合构建 → 风控 → F5模拟 → 成交/账户反馈。研究循环异步向策略注册器发布候选。告警订阅所有模块的事实。协调器负责时序，不插入投资判断。

## 5. 策略层必须先整理

策略层拆为三个职责，而不是继续以F4/F5编号作为产品业务：

1. 研究工厂：F4统一验证规则与Qlib候选，Qlib独立任务只管理自己的实验；研究任务失败只影响对应新发布。
2. 策略注册器：每个版本保存公式/模型哈希、训练与测试区间、股票池、成本假设、有效期、适用市场、参数边界、质量结论和准入通道。
3. 策略运行器：读取已发布版本，按同一预处理与推理代码生成信号，显式区分研究快照过期、模型过期、输入缺失和策略退役。

策略状态：draft → evaluated → paper_allowed → active → paused/retired。质量字段独立为qualified/unqualified/blocked；paper_allowed不能改写未通过绩效的事实。

实验模拟准入沿用现有政策：纯绩效未通过且数据/身份/未来数据/约束通过的版本可以进入实验模拟；完整性或未来数据失败的版本不可用。AI可以在许可池中自主选择，但不得将新公式、新模型、超范围参数直接用于活动账户。所有主动管理操作，包括仓位调整和策略切换，也必须在整条决策政策的样本外回放中验证，不能拿单一因子回测代替AI组合政策验收。

无可用策略时，明确输出no_eligible_strategy并保持已有持仓管理/风险监控；不能为了成交而自动放宽门槛。新研究失败不立即废止尚在有效期且未撤销的活动策略；活动策略到期则暂停新增暴露并发出明确恢复任务。

## 6. AI自主范围与工具

第一版只部署一个投资决策Agent，不采用多个Agent投票。研究、复盘、诊断是它的任务类型；执行和风控是确定性服务。

允许工具：读取快照/因子/策略/账户/告警；请求数据服务定向补齐；提交白名单回测/训练任务；提交组合提案；读取成交与对账；请求暂停许可策略。工具有schema、幂等ID、超时、资源限额和可审计回执。

AI可以请求数据更新，但数据定时采集不依赖AI是否回应。训练与回测进入研究队列，不阻塞盘中行情和订单；研究产物通过门禁后才可发布。

模型输出必须包含：decision_id、cycle_id、model_id、prompt_version、evidence_bundle_id、account_version、策略版本、action（hold/rebalance/reduce）、目标权重、有效截止时间、理由证据引用。价格、持仓与权益由服务端注入；AI不得自己声明授权。

hold为正常决策，必须保存原因。rebalance在约束内可自动执行；reduce仍受T+1、停牌、价格有效性约束。“停止新增决策”和“紧急停止全部撮合”分开定义，避免kill switch在不同模块含义相反。

模型请求首版预算：一次30秒超时，最多一次修复格式的重试；总周期60秒截止，超时后终态记录planner_timeout。每账户仅一轮活跃决策，后续普通事件合并。已有可信成交继续结算与对账；新的风险动作具有更高优先级。模型不可用时不生成新AI买入提案，独立风险监控继续运行。

公告和新闻属于不可信文本，只提取带出处的事实，不执行其中指令。模型无shell、文件系统任意写入或密钥读取权限。模型回复、工具参数、拒绝原因与可重复回放输入分别归档；只保存简洁决策解释，不要求模型内部思维过程。

## 7. 时间与状态流程

以下为目标设计参数，不是对现有运行频率的声明；实施前以交易日历和数据源可用时间作契约测试。

| 时段/触发 | 工作 |
|---|---|
| 盘前09:00 | 协调器检查最新完整数据、活动策略、模型连接、上日对账；每一阻断带owner/retry_at |
| 09:20 | 生成盘前组合提案；此阶段不模拟成交 |
| 09:35–11:25、13:05–14:45 | 每5分钟一次AI决策周期；无变化输出hold，不强制交易 |
| 盘中风险事件 | 风控立即产生动作/阻断，不等待AI；投递给执行器复核市场约束，并通知AI |
| 订单终态/对账异常 | 更新账户，触发复盘或阻断；普通成交事件合并到下一周期，避免无限再规划 |
| 14:50 | 停止新增常态调仓；允许既有工作结算/对账和已有风险政策规定的动作 |
| 盘后16:20 | 日线、PIT质量、因子、研究选股及评估；完成后一次发布 |
| 20:30 | 对相同目标日幂等补偿未完成研究 |
| 周研究 | F4/Qlib在研究队列按各自计划运行，保持独立生命周期 |

一个周期：created → collecting → deciding → validating → executing → reconciling → completed；无交易为held，业务阻断为blocked，已知错误为failed，结果未知为recovery_required。terminal状态必须带原因和下一动作；running必须带owner、lease和截止时间。

模型失败影响决策；缺行情影响相关证券或本次调仓；订单拒绝影响该订单；账本未知副作用或对账失败影响整个账户。错误恢复要按范围处理，禁止任意失败都升级为系统熔断，也禁止无限重试。

## 8. 统一数据与策略契约

快照区分event_time（交易或披露时间）、received_at（采集时间）、published_at、valid_until、source、coverage及quality。抓取时间推进不能证明上游行情更新；不同来源补入的成交额和价格各自保留时间。未闭合日K与完整日K有不同类型。

DecisionProposal必须绑定FeatureSnapshot和AccountSnapshot。verifier验证schema、证券存在、版本、权限、有限值和有效期；组合构建器检查权重、现金、股票池、行业；RiskDecision验证组合和各单的执行许可。风控通过后如账户版本变化，应重新核验，不能用旧许可消费新账户。

StrategyRelease是执行侧唯一策略输入合同，包含证据引用而非整份嵌套报告。F5最终不再遍历F4目录、QlibRecorder或解释研究latest状态；这些校验在发布和准入时完成，撤销/过期事件向运行器传播。不能通过缓存StrategyRelease来忽略撤销或有效期。

## 9. 执行层与唯一账本

保留F5撮合、费用、现金/持仓/成交、对账算法与历史数据。抽离其研究报告加载职责，提供内部execute_approved_target入口，由同一个受控协调器驱动。Web“运行一次”仅入队，所有入口共享账户级互斥与幂等身份。

第一版数据存储继续使用现有SQLite。决策、周期、工具回执是控制记录，可新增到同一F5控制存储中；它们不形成第二套现金和持仓。账户事件只由执行/结算服务写入，Web、AI和研究均只读。

订单终态包含filled、rejected、cancelled、partially_filled_cancelled；后者记录已成交量和取消量。剩余需求在新的子批次重新受检，原订单不被改成全成。未知回执先按幂等ID查证，不直接重发。订单容量、T+1、费用、现金预留和订单数上限继续在确定性组件验证。

日频和盘中不再作为两套活动执行时钟：盘中执行统一调仓；盘后入口负责结算/对账/次日准备，不再独立撮合另一套备用单。切换前先完成现有prepared批次的处置与回放。

同日允许多轮AI决策时，现有“日内首次target_qty冻结”必须迁移为按decision_id冻结目标。相同决策的子批次不能漂移；新的决策有新的版本，旧批次先完成或取消再切换。T+1日期只按交易日推进，不能因组合ID或decision_id改变就重置可卖量。

## 10. 风控与告警闭环

统一RiskPolicy版本，由配置持有数值。风险服务分别输出指标与最终许可：allow/reduce_only/halt/unknown。网页展示这些结果，不重算规则。风险高但仍允许某种操作时必须列出规则原因；展示等级不得隐式放宽或替代逐单许可。

事前：检查证券规则、行情、现金/预留、权重/集中度、订单数、策略/提案有效期。事中：按同一账户事实监测回撤和规则触发；获准的减仓也通过执行市场约束。事后：对账与异常升级。所有规则的输入缺失为unknown，不能填0后判低风险。

告警直接订阅RiskDecision、DataQualityChanged、TaskFailed、ReconciliationFailed和DeliveryFailed。先做事实生成，再做投递；AI解释是可选附件。告警不得再反向决定综合风险等级，避免风险→告警→风险的循环。

每条告警含alert_id、fingerprint、事件来源、严重度、first_seen、last_seen、输入时间、影响账户/证券、owner、处置动作、retry_at及恢复证据。相同事实去重更新计数。状态active → acknowledged → resolved，静音仅控制通知。页面无活跃告警时仍要显示last_evaluated_at与监控健康；若评估器停了显示“监控不可用”。第一阶段通知在本地Web；没有配置外部渠道时明确未配置，不声称已送达手机。

## 11. Web业务导航

保留现有组件逐步调整投影：驾驶舱显示账户、AI当前周期、许可、目标与未完成动作；策略页分研究实验/许可策略/当前运行；模拟执行页显示决策→目标→订单→成交→对账的关联ID；风险页显示规则、实际输入与许可；告警页显示评估器活性、事件与投递回执。F4/F5编号保留在技术详情与审计，不再作为用户理解交易的先决条件。

## 12. 渐进迁移与完成门槛

| 里程碑 | 改造范围 | 可验收结果 |
|---|---|---|
| M0 现状基线 | 注册当前入口、状态、配置与写入者；建立版本管理/发布证据 | 每个账户只有一个执行owner；数据/风险/告警缺失都可观测；保留回滚快照 |
| M1 策略发布 | 在quant/strategy建立注册/发布/运行接口，F4/Qlib作为候选来源 | 最新研究失败不覆盖有效活动策略；过期/撤销即时阻断；同一发布包可回放 |
| M2 风控告警 | 统一RiskPolicy/Decision及告警事件源，校验现有T+1/现金/部分成交 | 故障矩阵通过，API与UI许可一致；监控停机不显示绿色 |
| M3 AI影子决策 | 新增quant/decision，复用模型连接；先影子回放 | 有策略选择、目标权重、hold和解释；与无AI基线按同一输入比较 |
| M4 AI自治模拟 | 新增quant/runtime协调器，接入现有F5；切换唯一执行owner | AI真实模型回应驱动至少一个受检模拟调仓并成交/对账；10个完整交易时段内无重复副作用、无对账缺口 |
| M5 迁移清理 | 取消旧活动时钟和写入口，归档旧说明，更新只读兼容API | 依赖测试证明无活动引用后删除死代码；历史事实与可回放数据保留 |

每个里程碑只有一个接口切换点。影子期旧执行器可保持活动，新AI没有写权限；正式切换在无未决订单且账本对账通过时进行，唯一owner切换必须原子化。回滚仅在同样静止条件下恢复旧owner，绝不重放已经成交的订单。

工程风控验收矩阵必须覆盖：模型超时/非法JSON/越权参数；数据过期/假新时间/部分市场覆盖；策略过期/撤销；账户版本变化；T+1当日新买不可卖且换决策ID不解锁；停牌/涨跌停；部分成交；未知回执；重复触发；结算崩溃；对账失败；告警投递失败；Web关闭与API重启。前一版测试通过数不替代这些新增验收。

10个交易时段是可靠性观察目标，不是策略盈利证明。策略绩效与风险调整收益另用冻结候选、成本后样本外和AI对照试验判定。缺乏优势时必须如实记录，而不是为了“自主”增加换手。
