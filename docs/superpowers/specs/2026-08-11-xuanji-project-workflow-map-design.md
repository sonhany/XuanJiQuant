# XuanJiQuant 项目全景工作流设计

## 1. 目标

为 XuanJiQuant 建立一套类似 ComfyUI 的交互式项目思维图，用统一画布解释底层设施、前端、Node 后端、Python 量化内核、数据与研究流水线、Agent 自治、风险控制、模拟执行、审计和运维之间的真实关系。

图谱用于架构理解、故障定位、职责划分和项目交接，不作为运行控制面，不发起交易，不修改配置，不绕过 verifier、风险网关或 Agent-only 权限边界。

## 2. 输出

1. 一份浏览器内可交互的本地 HTML 可视化，位于 Codex 可视化工作区。
2. 一份项目内长期保存的架构分析文档 `docs/XUANJI_SYSTEM_WORKFLOW_MAP.md`。
3. README 增加上述文档入口，不重写既有架构章节。

## 3. 信息架构

可视化包含一个总控画布和八个专题视图：

1. 全局架构：React/Vite → Node API/控制层 → Python Runner → Quant 内核 → 存储/外部数据源。
2. 数据底座：市场行情、财务、资讯、PIT、Qlib、缓存、同步、质量与新鲜度门禁。
3. 研究流水线：因子构造、IC/IR、中性化、回测、策略工厂、Qlib、候选与影子证据。
4. Agent 自治：上下文、证据、规划、决策、验证、风险许可、执行授权和恢复状态。
5. 模拟交易：目标组合、订单生成、撮合、部分成交、持仓/现金、对账与恢复。
6. 风险与审计：硬限制、组合/宏观风险、告警、事件账本、运行日志和回放。
7. 前后端映射：主要 React 页面到 API 路由、PersistentRunner、Python runner、Quant 模块和事实存储的映射。
8. 运行状态：当前端口、进程、API、调度器、数据状态和 Agent 状态，作为带采样时间的独立快照展示。

## 4. 节点粒度

采用模块加关键类/函数/API/数据库表的语义粒度。总节点规模控制在约 60–100 个，避免直接铺开 Graphify 的全部代码节点。每个节点可以包含：

- 名称与所属层；
- 主要职责；
- 关键输入和输出；
- 源码路径或运行事实来源；
- 权限边界；
- 当前状态和采样时间；
- 已知风险或架构债务。

## 5. 连线语义

- 蓝色实线：数据流。
- 紫色实线：Agent 决策流。
- 红色实线：风险阻断、验证或权限控制。
- 绿色实线：订单、成交、持仓和资金流。
- 橙色实线：调度和后台任务。
- 灰色虚线：日志、审计、状态或证据回传。

连线必须来自源码、现有 Graphify 图谱或明确的架构文档。无法验证的关系不画成确定连接。

## 6. 交互设计

- 顶部切换总图与专题视图。
- 支持关键词搜索、层级筛选和连线类型筛选。
- 支持缩放、平移、自动适配画布和恢复默认视图。
- 点击节点打开详情面板，显示职责、上下游、源码入口、状态、风险和边界。
- 节点状态使用正常、关注、阻断、未知四类徽标；运行状态必须显示采样时间。
- 图例固定可见，中文为主，代码符号保留原名。

## 7. 证据口径

每条信息标记一种证据等级：

- `源码验证`：从当前工作区源码或 Graphify 源码位置得到。
- `文档声明`：来自 README、XUANJI_HANDOFF 或已批准规格。
- `运行快照`：本轮从进程、端口或 API 实际读取，必须附采样时间。
- `待核实`：无法在本轮安全验证，只能作为明确的缺口显示。

历史缓存、旧日志、调度器存在和进程存在均不能单独证明业务成功。

## 8. 当前状态边界

运行快照只做只读检查：Web `127.0.0.1:8888`、API `127.0.0.1:8880`、本项目进程、Agent runtime、研究调度、数据同步与模拟执行状态。不得读取或操作冻结备份 `C:\Users\HYSHEN\AlphaCouncil2-AI`，不得触发模拟交易或真实交易。

## 9. 完成判定

只有同时满足以下条件才算完成：

1. 总图和八个专题视图均可切换。
2. 搜索、筛选、缩放、平移、节点详情和重置均可使用。
3. 核心链路均能回溯到当前源码、文档或带时间戳的运行快照。
4. 数据、Agent、风控、执行和审计的权限边界在图中可见。
5. 项目内架构文档与可视化采用同一套节点和关系口径。
6. HTML 不依赖外网请求，浏览器控制台无错误，常见桌面尺寸下无关键内容溢出。
7. README 提供交接入口，且不修改原有业务实现。
