# 基于成熟交易框架的 AI 自主模拟量化系统基准设计

日期：2026-09-11。性质：独立目标架构与重新评估，不代表功能已实施或通过验收。

范围：AI自主研究、策略管理、组合决策、模拟交易和复盘；不建设券商接口。此设计取代上一份架构草案中“优先保留当前F5实现”的预设。现有代码逐模块检验，符合契约才复用；历史账户事实保留。

## 1. 外部基准与推导范围

本轮通过官方网页核实以下公开设计；搜索工具不可用，使用HTTP直接读取官方文档。

- LEAN Algorithm Framework：股票池 → Alpha/Insight → PortfolioTarget → Risk Management → Execution，并明确关注职责分离及组合换手问题。https://www.quantconnect.com/docs/v2/writing-algorithms/algorithm-framework/overview
- NautilusTrader Architecture：数据、风险、执行、组合及消息总线，共享backtest/sandbox内核，事件有序处理，研究与运行环境隔离。https://nautilustrader.io/docs/latest/concepts/architecture/
- NautilusTrader Execution：订单生命周期、成交去重、持仓映射、未知结果与执行对账。https://nautilustrader.io/docs/latest/concepts/execution/
- Qlib Workflow：数据、训练推理、信号评估、回测与实验记录。https://qlib.readthedocs.io/en/latest/component/workflow.html
- Qlib Online Serving：更新预测、安排训练任务、选择在线模型与生成信号；数据源持续更新由使用者保障。https://qlib.readthedocs.io/en/latest/component/online.html

这些产品提供工程参考，不构成某一种LLM全权交易方式已被行业普遍验证的证据。下面的AI职责、模拟验收和部署方案是基于参考设计的本项目建议。采用框架也不自动保证A股规则、数据质量或盈利能力。

## 2. 产品定义

在预配置的研究范围和模拟资金预算内，系统自主研究、评估、发布策略、选择策略、分配资金、模拟成交、核算账户、处理异常并形成可追溯反馈。允许持币和不交易，不用成交数量衡量AI是否工作。

AI包括两类不同能力：统计/机器学习模型产生可验证的预测信号；语言模型负责研究任务规划、文本信息提取、候选/策略选择及有界组合决策。每类能力都有独立输入输出、版本、成本和有效性评估。

正常运行不用人工逐笔确认；人工设定自主范围、查看风险、暂停系统及批准自主范围的扩大。运行中的AI不能更改资金安全预算、真实交易能力或审计事实。

## 3. 整体结构：三类运行职责

### 研究平台

原始数据归档 → PIT与证券主数据 → 特征/标签 → 因子研究与模型训练 → 走样本外评估 → 组合及模拟成本验证 → 策略/模型注册 → 版本发布。

研究可以失败、重试或没有发现有效策略；失败不会覆盖已发布且仍有效的版本。数据正确性、执行可行性、样本外绩效是三个独立结论。实验模拟可以接纳政策明确许可的绩效未通过候选，但必须带unqualified标签，不能绕过数据和执行约束。

### 在线交易内核

市场事件 → 特征更新 → 活动策略信号 → AI决策 → 组合构建 → 事前风控 → OMS/执行算法 → 模拟撮合 → 成交事件 → 账户核算 → 对账。

同一账户的订单、成交与账户事件有序处理。实时路径不执行全量训练、不扫描研究目录、不等待LLM无限回复。训练推理需要时通过隔离工作进程返回明确结果。

### 控制与运维

负责配置版本、组件生命周期、任务调度、资源预算、日志、指标、告警、恢复、操作员控制和Web/API投影。服务启停和交易时钟独立于浏览器与聊天工具。智能研究能力不具有修改在线程序的权限。

## 4. 模块合同与责任

| 模块 | 输入 | 输出/唯一责任 |
|---|---|---|
| 证券主数据/交易日历 | 交易所和可信主数据 | 证券身份、上市退市、交易时段、最小单位、公司行动 |
| 数据服务 | 行情、财报、公告等 | 带来源、事件时间、采集时间、质量和覆盖率的规范化数据 |
| 特征服务 | 版本化数据、特征定义 | FeatureSnapshot；研究与在线使用相同计算定义 |
| 研究评估 | 特征、标签、候选、实验政策 | ResearchReport；记录所有尝试，防止事后挑选结果 |
| 模型/策略注册器 | 验证结果和完整产物 | StrategyRelease；质量、许可范围、有效期、撤销状态 |
| 策略引擎 | StrategyRelease、FeatureSnapshot | Signal；方向、预期收益/分数、预测周期、有效期、来源版本 |
| AI决策服务 | 信号、市场证据、账户、可用策略 | DecisionProposal；策略选择、风险预算内资金分配、调仓/持有理由 |
| 组合管理 | 决策提案、当前持仓和在途订单 | TargetPortfolio；约束、相关性、集中度、现金及换手成本 |
| 独立风控 | 目标/订单、账户版本、市场状态、RiskPolicy | RiskDecision；许可、原因、限额和有效期 |
| OMS/执行 | 已许可目标及订单 | 有序订单生命周期、拆单、撤单、重试、超时、幂等 |
| 模拟撮合 | 订单、行情及SimulationConfig | 明确假设下的确认、成交、拒绝和取消事件 |
| 会计与对账 | 成交、费用、公司行动、资金事件 | 现金/冻结资金/持仓/可卖量/权益/盈亏；异常差异 |
| 监控告警 | 各模块事件与心跳 | 去重、升级、派发、恢复证据及通知回执 |

任何跨模块调用使用有类型的接口或事件；不得读取对方私有表或随意拼接文件路径。模块不可反向依赖CLI/API入口。Web只读同一投影；页面刷新不得启动交易、结算或重训练。

## 5. 策略层重新定义

策略不等于因子榜单，也不等于一个F4状态。完整策略版本必须定义：适用股票池、输入特征、信号计算、预测/持有周期、进入退出规则、组合政策、成本容量假设、适用市场、监控指标和失效条件。

研究工厂输出候选；注册器决定版本是否可用于实验模拟或验证模拟；策略运行器只加载已发布版本。Qlib是其中一个模型研究与预测来源，F4可以是评估服务的实现，两者都不是交易内核总开关。

必须区分四种频率：模型训练、在线推理、组合再平衡、订单执行。日频模型可以在盘中使用最新行情执行，但不会因每分钟调用LLM就成为分钟级预测策略。AI切换策略或调权的政策也要被评估，单策略通过不等于其任意组合通过。

多策略先在组合层做净额与资金分配再下单，保留每个策略的贡献归因，避免同一账户内策略相互买卖消耗成本。

## 6. AI自主闭环

### 研究职责

AI从数据质量、因子失效、策略绩效和市场变化提出研究假设，调用有预算的白名单训练/回测工具，比较验证结果，提交或在许可政策内自动发布模拟候选。新代码只能在隔离研究环境产生与测试，经过发布门禁才进入策略版本；没有在线改代码权限。

### 交易职责

AI读取结构化的当前市场、活动策略信号、账户与风险预算；选择策略、分配权重或现金；提交结构化决策。组合管理器给出可行目标，风控独立核验后由OMS执行。获批范围内不需要人工每轮批准。

语言模型没有提供价格和成交事实的权威。每次决策记录模型版本、提示版本、证据版本、账户版本、输出、校验结果和行动回执。新闻/公告文本作为数据处理，不可成为工具调用指令。

### 反馈职责

成交反馈更新账户；绩效归因区分信号误差、策略选择、仓位配置、执行成本和市场冲击。AI提出可测试的调整；不因一笔亏损立刻重训练或无限切换策略。候选与当前版本进行共同输入和成本假设下的对照实验。

验证AI价值必须同时测量：模型可用率、工具错误率、越权提案拒绝、决策延迟、模型调用成本、换手变化和样本外成本后收益。历史新闻回放需说明LLM预训练知识可能引入未来信息；前向影子结果单独报告。

## 7. 模拟必须具备真实业务约束

回测与在线模拟共用信号、组合、风控、订单和会计核心；切换历史/实时数据与模拟时钟。禁止一套“简单回测”证明收益、另一套模拟代码执行账户。

模拟器覆盖：交易时段、证券状态、买卖单位、T+1、价格限制、价格精度、费用、现金预留、成交延迟、滑点、部分成交、撤单和公司行动。规则按证券类别和版本配置。具体费率/规则在实施时核对对应官方材料。

只有Level-1或分钟数据时，不能证明真实排队位置、逐笔可成交量或精确冲击成本；输出必须标注模拟模型和假设。完整性上采用保守成交假设及成本压力测试，不把模拟盈利解释为实盘可复制。

关键账户恒等式：权益=现金+持仓市值；成交数量不重复记账；冻结资金和已用资金不可重复可用；当日买入不可因切换策略或重启解锁；手续费和已实现盈亏有明细。基于事件重建的账户必须与快照相符。

## 8. 风控、告警与恢复

风控分事前、事中、事后，由同一政策版本与账户事实驱动。展示风险等级与最终执行许可分字段，所有拒绝可解释，参数冲突需在发布前被拒绝。风险事件直接进入确定性控制流程，不等待AI同意。

告警消费风控/数据/任务/订单事实；不反过来以“告警数量”循环决定风险。没有风险数据或评估器心跳过期时显示unknown/unavailable，不显示健康或零告警。确认/静音不解除风控状态，只有重新验证的恢复事实才能解除。

故障按范围处理：模型异常暂停新AI提案；单股数据缺失隔离受影响证券；局部拒单不升级整个账户熔断；账户差异、重复成交疑点或未知副作用隔离账户并先对账。持仓管理在可获得可靠行情和账户事实时按预设保护规则继续；无法判断可安全执行时停止撮合。

技术上允许事件重投递，但必须通过持久事件ID/订单ID去重。进程重启先恢复未终态订单并对账，再释放新决策。重试设截止时间和退避；任何running状态都要有owner、心跳、截止时间、下一动作。

## 9. 工程与部署

首版使用清晰的模块化内核，按职责隔离成交易进程、研究工作进程、AI工作进程、Web/API与监控进程。共享typed contracts，避免为每个小模块部署微服务。

建议产品级事务存储使用PostgreSQL保存控制记录、订单事件与账户状态；不可变历史数据/模型产物采用Parquet及对象存储接口，可先部署本地磁盘。内存/Redis仅为可重建缓存。该建议不是当前数据库迁移指令，选择前需要在目标机器完成依赖、备份恢复、并发与故障验证。一个账户只有一个逻辑账本，与表和存储介质数量无关。

引擎选择先做可替换接口和有限验证：LEAN用于检验组合型策略框架适配，NautilusTrader用于检验事件内核/模拟执行适配。先测A股规则、当前Windows部署、历史回放及性能，再确定其中一个交易核心；不能拼装两套活动OMS。Qlib独立承担研究工作流。

生产工程要求：版本库、锁定依赖、自动测试、发布制品、迁移脚本、备份恢复演练、配置版本、结构化日志、指标和告警。测试环境不写活动账户，发布前有回放和故障注入。恢复目标必须用演练实测，不能因端口恢复就宣布交易恢复。

## 10. 交付阶段和退出标准

| 阶段 | 交付 | 必须证明 |
|---|---|---|
| A 基准与引擎验证 | 目标契约、成熟内核适配实验、同一固定历史样本 | 信号/风控/订单/会计一致，关键A股规则覆盖，明确引擎选择 |
| B 确定性交易系统 | 数据、策略运行、组合、OMS、模拟、风险、会计 | 无AI也能用固定基线完整回放/模拟；故障恢复与对账通过 |
| C AI研究与影子 | 有预算的研究工具、模型/策略注册、影子组合 | 有真实模型响应与工具证据，对照实验有效，无在线越权 |
| D AI自主模拟 | 账户唯一owner切换、事件决策、保护规则、复盘 | 每次成交可追溯到AI决策；hold有原因；多日无重复结算/未知挂起 |
| E 产品验收 | 全功能、性能、故障、备份、监控和权限验收 | 每个故障都有检测与恢复证据，用户能看到收益来源、风险依据和阻断负责人 |

模拟自治初始验收目标为连续20个交易日的完整运营证据，加独立故障注入测试；这是建议可靠性观察窗，不是行业统一标准，也不是收益保证。期间零重复账户副作用、零未解释对账差异；每个应执行周期有终态与原因。性能SLO由阶段A按股票池、策略周期和硬件确定，以P95/P99和数据年龄验收，不能用平均延迟代替。

当前模块只按以下决定去留：符合新契约且回放验证通过则复用；耦合严重且可隔离则提取；无法证明正确则替换。历史账本不因重构被删除。任何旧实现的便利都不构成降低验收标准的理由。

## 11. 对上一版草案的修正

- 不再预先认定现有数据、因子和F5可直接保留，全部需要契约验收。
- 增补证券主数据、公司行动、组合管理、OMS、会计对账、模型注册与运营能力。
- 五分钟只作为现有时钟信息；未来频率由策略预测周期和性能验证决定。
- 将AI决策政策本身纳入实验和样本外验证，不以“模型能调用工具”作为完成标准。
- 采用研究、交易、控制职责隔离；先评估成熟内核，再决定自研范围。
- 本轮是目标设计交付，没有安装框架、更换数据库、修改运行代码或启用新AI控制面。
