# 巨潮公告市场资讯接入设计

## 目标

在现有“市场资讯”工作区内增加与“金十数据”同级的“巨潮公告”页签。金十继续承担宏观行情、快讯、新闻与财经日历；巨潮承担 A 股上市公司公告检索和官方原文跳转。

## 页面结构

- 保留左侧单一“市场资讯”入口，避免导航膨胀。
- 市场资讯页面顶部增加“金十数据 / 巨潮公告”分段页签。
- 金十页签直接复用现有 `Jin10DataPanel`，不修改其数据和交互逻辑。
- 巨潮页签提供“最新公告 / 业绩快报 / 业绩预告”三个视图。
- 支持股票代码、关键词、开始日期和结束日期查询；默认查询最近 30 天。
- 公告列表展示股票代码、股票简称、公告标题、公告日期、公告标签和官方 PDF/详情链接。

## 数据链路

前端只调用本地 `POST /api/cninfo`。Node 路由通过独立持久 Python 进程调用巨潮公告查询接口，不与金十 MCP 进程混用。请求字段限制为 `action=query`、股票代码、关键词、预设类型、日期范围、页码和每页条数。

后端最多返回 50 条/页，最多允许查询 366 天范围；默认缓存 5 分钟。缓存命中不访问上游，手动刷新可显式绕过缓存，但仍受单进程最小请求间隔控制。上游异常返回明确错误，不伪造空的健康结果。

## 安全与研究边界

- `/api/cninfo` 是只读接口，不接受交易、下载文件到本地或执行任意 URL。
- PDF 链接只允许巨潮官方域名，公告标题移除上游高亮 HTML。
- 公告保留真实 `announcement_time` 和 `announcement_id`，供 point-in-time 审计和去重。
- 巨潮公告只进入资讯/事件研究层，不直接触发订单，不绕过 verifier 或 risk gateway。
- 页面明确说明网页查询接口无 SLA，生产和商业批量使用需确认授权。

## 错误与空状态

- 网络失败、限流、无效 JSON、日期非法分别返回可读错误。
- 无结果时展示当前筛选条件下没有公告，并提供清除筛选操作。
- 首次加载使用结构化骨架；查询按钮在请求期间禁用，避免重复提交。

## 验证

- Python 单元测试覆盖输入归一化、标题清洗、官方链接和缓存行为。
- Node 合同测试覆盖只读路由、面板挂载和前端查询契约。
- TypeScript、Vite 构建通过。
- 浏览器验证页签切换、查询结果、原文链接、空状态、移动端布局和控制台错误。
