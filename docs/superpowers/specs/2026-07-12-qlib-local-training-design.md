# Qlib 本机训练与中文研究控制台设计

## 1. 目标

在不影响现有盘中数据采集、AI 调度、模拟盘和风险网关的前提下，把当前
`local_adapter_only` 的 Qlib 页面扩展为真实可用的离线研究系统。

第一阶段交付一个可重复训练、加载、预测和回测的 LightGBM 基线模型：

- 特征：Qlib Alpha158 + 项目自研 58 因子。
- 标签：未来 5 个交易日相对市场基准的超额收益。
- 范围：符合资格条件的全 A 股。
- 输出：股票预测分数、截面排名、模型置信度、模型版本和数据日期。
- 权限：模型只进入 `candidate` 或 `shadow`，不得直接提交订单。

Qlib 不直接使用现有交易系统的 `quant.db` 作为训练数据源。首先下载 Qlib
官方示例中国数据完成安装和训练冒烟；随后由独立采集进程重新下载近一年全 A
日线，验证完整训练流水线。首轮验证通过后，在独立数据仓内补齐近六年全 A
日线，并重新训练正式研究基线。


```text
C:\Users\HYSHEN\AppData\Local\Programs\Python\Python311\python.exe
Python 3.11.9 / 64-bit
```

不重复安装系统 Python，不使用其已有第三方包。通过该解释器创建干净的
`.venv-qlib`，从锁定的依赖文件重新安装 Qlib 训练依赖。现有 Python 3.11
全局环境存在包版本冲突，因此训练任务不得直接调用系统 Python。

不替换当前项目使用的 Python 3.14，不把 Qlib、PyTorch 或训练依赖加载到
Web API 和盘中交易进程。Qlib 任务由独立 worker 执行，Web 后端只负责鉴权、
提交任务、查询状态、读取实验结果和请求取消。

不在第一阶段使用 WSL2 或 Docker，以免增加 TdxQuant 本地数据桥接、Windows
GPU 映射和目录权限复杂度。

## 3. 系统架构

```text
Qlib 中文研究页
       |
       v
Qlib 任务管理 API
       |
       v
任务表 + 单任务锁 + 审计记录
       |
       v
.venv-qlib Python 3.11 worker
       |
       +--> Qlib 官方示例数据冒烟
       +--> 独立采集器下载一年/六年全 A 日线
       +--> 原始层、标准层和数据质量校验
       +--> Qlib dump_bin 数据转换
       +--> Alpha158 + 自研 58 因子
       +--> DatasetH 与时间切分
       +--> LightGBM 训练
       +--> 样本外预测与现实约束回测
       +--> 模型、指标、配置、日志原子化保存
       |
       v
candidate --> shadow --> 既有 paper 晋升流程
```

同一时间只允许一个重型 Qlib 任务。训练任务不进入在线 API 进程，关闭浏览器
不会终止训练。主项目重启后从独立 Qlib 任务库恢复任务状态。Qlib 采集和训练
进程不读写交易系统 `quant.db`，也不修改现有数据源配置。

## 5. 数据规范

### 5.1 独立数据源

Qlib 研究数据不从现有 SQLite KV 复制。独立采集链路为：

- 安装冒烟：Qlib 官方示例中国数据，只验证环境、Alpha158 和模型训练。
- 正式日线主源：TdxQuant 独立调用，保存未复权行情和来源响应摘要。
- 历史交叉校验：Baostock。
- 最新交易日补齐和复核：腾讯。
- 股票池、名称和上市状态：独立获取并保存历史有效区间。
- 基准：独立下载宽基指数，代码、来源和版本写入实验配置。

允许复用经过验证的数据源适配算法，但 Qlib collector 使用独立进程、独立配置、
独立缓存和独立存储。它不得调用 `create_cache()`，不得写入 `quant.db`。

正式标准数据至少包含：

```text
instrument, datetime, open, high, low, close, volume, amount,
factor, paused, limit_up, limit_down, source, fetched_at, data_version
```

不能只保存前复权结果。原始层保存未复权价格及复权相关数据，标准层根据明确
版本生成 Qlib 使用的复权序列。这样可以重建口径、识别除权跳变并避免不同来源
的前复权历史被错误拼接。

### 5.2 股票资格

训练样本排除：

- `920xxx`。
- ST、`*ST`、退市整理和明确退市股票。
- 上市不足 120 个交易日的股票。
- 最近 20 个交易日有效数据少于 18 日的股票。
- 长期停牌、价格非正、成交量或成交额异常的股票。
- 标签窗口或特征窗口数据不足的记录。

所有过滤结果需要保存原因码。历史 ST 和退市状态若无法做到点时数据，必须在
实验报告中披露，不得把当前名称过滤描述为完整的历史点时过滤。

### 5.3 数据质量门禁

- 股票池覆盖率不低于 98%。
- 日线重复键为 0，键为 `instrument + datetime`。
- OHLC 关系、价格、成交量和成交额通过基本合法性检查。
- 数据最新日期与预期最近交易日一致，或明确记录缺口。
- 标签只使用特征日期之后的数据。
- 训练、验证、测试严格按时间切分，禁止随机打乱后切分。

### 5.4 存储

标准日线和大型因子矩阵优先保存为 Parquet。独立 `qlib_meta.db` 只保留任务
状态、数据清单、实验索引和审计记录，不保存完整六年因子矩阵。交易系统
SQLite 不保存任何 Qlib 大型研究产物。

## 6. 模型与评估

### 6.1 基线模型

- 模型：Qlib LightGBM。
- 目标：未来 5 个交易日股票收益减去同期基准收益。
- 任务：截面排序，不把预测值解释为确定收益率。
- 冒烟：Qlib 官方示例数据，标记为 `official_demo_smoke`。
- 首轮：独立重新下载的近一年数据，标记为 `short_sample_experiment`。
- 正式基线：近六年数据，包含滚动样本外评估。

### 6.2 时间切分

首轮按交易日期顺序切分 Train、Valid、Test。六年正式训练使用滚动
walk-forward：训练窗口、验证窗口和测试窗口均记录明确起止日期。任何标准化、
缺失值处理和特征选择只能在训练窗口拟合，再应用到验证和测试窗口。

### 6.3 评估指标

- Rank IC 均值、标准差、ICIR 和 IC 正值占比。
- 分组收益与 Top-Bottom 多空收益。
- 扣除手续费和滑点后的组合收益。
- 年化收益、Sharpe、最大回撤和换手率。
- Train、Valid、Test 分段稳定性。
- 行业、规模和市场状态分组稳定性。
- 特征重要性和预测覆盖率。

### 6.4 候选门槛

- 数据完整率不低于 98%。
- 测试集 Rank IC 均值不低于 0.02。
- 测试集 ICIR 不低于 0.30。
- 扣除费用后多空收益为正。
- 测试集策略 Sharpe 不低于 0.80。
- 最大回撤不高于 20%。
- Train、Valid、Test 不得出现明显方向反转。

未达标实验完整保留，但模型状态只能是 `rejected` 或研究记录，不得进入
`shadow`。达到门槛的模型先登记为 `candidate`，人工操作最多提升到 `shadow`。

## 7. 模型与实验产物

每次成功训练必须保存：

- 模型文件。
- SHA-256 校验值。
- Qlib、Python、LightGBM 和主要依赖版本。
- 数据版本、数据最新日期、样本数量和股票数量。
- 完整特征清单和标签定义。
- Train、Valid、Test 起止日期。
- 模型参数和随机种子。
- 预测文件、指标报告和回测报告。
- 任务 ID、实验 ID、模型 ID 和创建时间。

模型写入临时目录，全部文件完成并通过重新加载测试后再原子移动到正式模型
目录。中断或校验失败的目录不能登记为可用模型。

## 8. 中文研究界面

Qlib 页面改为以下中文页签：

1. `研究总览`：环境、GPU、独立数据仓、数据日期、最近任务和候选模型。
2. `数据准备`：官方示例、一年独立数据、六年独立数据的覆盖率和完整状态。
3. `模型训练`：安全参数预设、启动、取消、阶段进度和资源占用。
4. `实验记录`：数据版本、特征、样本、耗时、指标和实验比较。
5. `模型仓库`：模型版本、状态、文件大小、校验值和核心指标。
6. `回测评估`：IC、分组收益、扣费净值、回撤、换手和分段稳定性。
7. `任务日志`：安装、下载、导出、训练、回测和错误日志。

页面默认使用中文名称，必要的 Qlib 类型名和指标缩写同时保留中文解释。修复
当前 Qlib 前后端源码中的乱码字符串。

第一阶段只提供经过验证的参数预设，不开放任意命令、文件路径或 Python 参数
输入，避免命令注入和失控资源消耗。

## 9. API 与权限

API 支持：

- 环境和数据状态查询。
- 任务列表和单任务状态查询。
- 数据导出、短样本训练和六年补齐任务提交。
- 任务取消。
- 实验、模型、预测和报告查询。
- 模型从 `candidate` 人工提升到 `shadow`。

所有状态变更接口复用现有控制面鉴权。请求只能选择服务端定义的任务类型和
参数预设，不接收 shell 命令。任务操作写入结构化审计记录。

API 只读取独立 `qlib_meta.db` 和经过白名单约束的数据仓目录，不读取交易系统
`quant.db`。Qlib 预测进入现有系统时只通过版本化 `shadow_signal` 文件或受控
导入接口传递，不共享数据库连接。

## 10. 调度

- 手动：中文页面可启动数据检查、导出、训练和回测。
- 自动：每周六凌晨执行数据增量检查，满足完整性门禁后重训。
- 盘中：禁止启动重型训练，只读取最近一次有效预测。
- 自动任务失败：保留上一个有效模型，不自动替换。
- 六年补齐：支持断点续传、单股重试、失败清单和再次补齐。
- 独立 collector 不跟随交易系统的数据刷新任务启动，双方调度互不依赖。

## 11. 异常处理

- Python 3.11、pyqlib 或核心依赖缺失时拒绝启动训练并显示中文修复建议。
- PyTorch/CUDA 不可用不阻塞 LightGBM CPU 基线；深度学习任务必须拒绝启动。
- 单任务锁防止重复训练。
- 取消采用协作式取消和超时终止，任务最终状态必须明确。
- 任务进程异常退出后，启动恢复逻辑将运行中任务标为 `interrupted`。
- 磁盘空间不足、数据门禁失败、模型无法重新加载时，不生成候选模型。
- 日志不记录密钥、Token 或完整敏感请求头。

## 12. 测试与验收

### 12.1 自动测试

- 环境检测和解释器选择测试。
- 股票资格、标签对齐、时间切分和未来函数测试。
- 导出数据格式、重复键和缺失值测试。
- 模型训练、保存、重新加载和预测可复现测试。
- 指标门槛和模型状态机测试。
- 单任务锁、取消、恢复和失败状态测试。
- API 鉴权、参数白名单和路径安全测试。
- 中文页面组件和交互契约测试。

### 12.2 集成验证

- 完成一次近一年全链路训练和现实约束回测。
- Qlib 官方示例数据完成环境与训练冒烟，但不登记为正式候选模型。
- 独立一年数据由 Qlib collector 重新下载，训练过程不访问 `quant.db`。
- 生成至少一个可重新加载的 LightGBM 模型文件。
- 从中文页面启动任务并查看进度、结果、模型和日志。
- 使用浏览器插件验证页面身份、非空、无框架错误覆盖层、控制台健康和交互。
- 执行项目核心 Python 测试、Node 契约、前端构建和七层冒烟。
- 验证数据、因子、策略、模拟盘、AI 调度和风险网关没有受到回归影响。

### 12.3 六年任务验收

六年历史补齐任务必须成功启动并支持断点续传。只有覆盖率和数据日期达到门禁
后，才能执行正式基线训练。未完成的数据集必须明确显示为 `incomplete`，不能
冒充正式六年训练结果。

## 13. 非目标

第一阶段不包含：

- LSTM、Transformer 或强化学习正式训练。
- Qlib 模型自动进入模拟盘或实盘。
- 自动修改风险预算、仓位上限或 Kill Switch。
- 全市场 Tick 数据进入 Qlib 日频基线。
- 任意模型自动晋升为生产模型。

这些能力必须在 LightGBM 基线稳定、数据点时质量明确、shadow 和 paper 验证
完成后单独设计。
