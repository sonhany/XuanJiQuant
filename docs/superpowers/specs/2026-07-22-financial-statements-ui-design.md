# 财务报表专业排版设计

日期：2026-07-22  
状态：已确认  
选定方向：C - 决策优先混合表

## 目标

将现有财务报表从“数据库字段宽表”升级为适合专业投资者长期使用的财务分析界面，同时保持只读、数据完整和来源可追溯。

成功标准：

1. 用户无需心算即可区分金额、百分比、倍数和每股指标。
2. 三秒内识别股票名称、代码、最新报告期及六项核心财务指标。
3. 在一个屏幕宽度内完成同类指标的跨期比较。
4. 不重复展示股票名称、代码等身份字段。
5. 所有数据库字段仍可查看，未知字段不丢失、不猜测含义。

## 页面结构

### 1. 查询栏

- 保留股票代码输入框和查询按钮。
- 输入支持 `600519`、`SH600519`、`600519.SH`。
- 查询按钮在加载期间禁用并显示旋转状态。
- 辅助说明保持简短：仅查询本地数据库，不触发财务更新。

### 2. 股票身份栏

- 股票名称作为主标题，例如“贵州茅台”。
- 股票代码、推断交易所、最新报告期作为次级信息。
- 交易所仅按代码规则推断；接口未提供行业时不显示行业标签。
- 数据集数量与历史报告期数量降为辅助状态，不占用核心指标位置。

### 3. 最新一期摘要

从最新历史记录读取六项核心指标：

- 营业收入
- 净利润
- 经营现金流
- 净资产收益率
- 毛利率
- 资产负债率

摘要使用紧凑六列网格；中等宽度变三列，小屏变两列。金额、比率都显示明确单位。缺失值统一显示 `--`。

### 4. 指标分组表

使用紧凑分段控制器切换同类指标：

| 分组 | 字段 |
| --- | --- |
| 利润与现金流 | `revenue`、`net_profit`、`operating_cash_flow`、`enterprise_fcf_per_share`、`shareholder_fcf_per_share` |
| 盈利能力 | `roe`、`roa`、`gross_margin`、`net_margin` |
| 成长能力 | `revenue_growth`、`profit_growth` |
| 偿债与运营 | `debt_ratio`、`current_ratio`、`inventory_turnover`、`receivable_turnover`、`asset_turnover` |
| 其他指标 | 历史记录中存在、但不属于上述已知字段的所有列 |

表格规则：

- 报告期固定在左侧，表头固定在顶部。
- 不再逐行重复股票代码和股票名称。
- 默认显示“利润与现金流”。
- 每组只展示相关指标，减少无意义横向滚动。
- 表格仍支持横向滚动，以容纳动态字段。
- 数据按最新报告期在前排序。

### 5. 数据库原始数据

- 保留所有 `fin:*:<code>` 数据集。
- 原始数据默认折叠，避免干扰主要分析。
- 展开后仍支持嵌套字段路径、完整值和独立滚动。
- 原始字段名使用等宽字体，业务展示使用中文标签。

## 数字格式

### 金额

采用用户确认的自适应单位：

- 绝对值大于等于 `100,000,000`：显示亿元。
- 绝对值大于等于 `10,000`：显示万元。
- 其他金额：显示元。
- 默认保留两位小数并使用千位分隔。
- 单元格 `title` 保留完整人民币原值，例如 `¥54,702,912,385.23`。

适用字段：`revenue`、`net_profit`、`operating_cash_flow`。

### 百分比

数据库中的比率值按“百分数”直接显示，不再乘以 100。例如 `10.57` 显示为 `10.57%`。

适用字段：

- `roe`
- `roa`
- `gross_margin`
- `net_margin`
- `revenue_growth`
- `profit_growth`
- `debt_ratio`

只有增长率使用正负颜色：正值绿色、负值红色、零值中性。ROE、毛利率和负债率等状态指标保持中性色，避免把“数值高”错误表达成“必然更好”。

### 倍数

`current_ratio`、`inventory_turnover`、`receivable_turnover`、`asset_turnover` 显示为 `x.xx 倍`。

### 每股指标

`enterprise_fcf_per_share`、`shareholder_fcf_per_share` 显示为 `x.xx 元/股`。

### 未知字段

- 数字使用千位分隔，最多保留六位小数。
- 不擅自追加单位。
- 字段原名通过标题或原始数据区保留。

## 视觉规范

- 延续现有深色工作台，不引入新主题和渐变。
- 黄色仅作为当前分组、查询按钮和重点身份标识。
- 涨跌红绿仅用于增长率正负，不作为装饰色。
- 数字使用等宽字体和 `tabular-nums`。
- 主体文字不小于 12px；指标名 11-12px；核心数值 16-18px。
- 使用 4/8px 间距节奏，圆角不超过 8px。
- 表格行悬停只改变背景色，不改变尺寸。
- 键盘焦点必须可见，按钮保持语义化元素。

## 数据与组件边界

前端不修改后端数据结构。页面内部新增：

- 字段元数据：中文标签、类型、分组、单位。
- 统一格式化函数：金额、百分比、倍数、每股指标、原始值。
- 最新报告期摘要组件。
- 指标分段控制器。
- 分组财务表组件。

现有 `FinancialStatementsPanel` 继续负责查询和页面状态。数据格式化和列选择使用 `useMemo`，避免 102 期数据在每次输入时重复计算。

## 错误与空状态

- 非法代码：输入框附近显示明确错误。
- 无财务数据：显示股票代码、名称及“数据库暂无财务数据”。
- 单个指标缺失：显示 `--`，不隐藏整行。
- 未知字段：进入“其他指标”和原始数据区。
- API 失败：保留现有错误提示，不显示旧股票的数据作为新查询结果。

## 验证

1. 单元/契约测试覆盖各字段类型的格式化规则。
2. 验证正负金额、零值、空值和非有限数字。
3. 验证代码与名称不在历史表中重复。
4. 验证所有动态字段均进入某个分组或原始数据区。
5. TypeScript、Vite 构建和现有财务接口测试通过。
6. 浏览器验证 1280、1440、768 和 375 宽度。
7. 检查键盘查询、分组切换、横向滚动、固定表头和控制台错误。

## 非目标

- 不新增财务图表。
- 不计算数据库未提供的同比、环比或估值指标。
- 不修改财务采集、数据库结构或更新任务。
- 不引入第三方 UI 或表格依赖。
