# 因子层端到端工作流可视化设计

## 1. 目标

为 XuanJiQuant 建立一份独立、只读、可交互的因子层全景工作流图。视觉与交互参考 ComfyUI 的节点式工作流，但不接入或修改项目运行代码，不提供生产任务执行能力。

该图用于整体分析因子层状态，使使用者能在一分钟内回答：

- 原始市场与财务数据从哪里进入因子层；
- 58 个固定因子如何计算、物化和评估；
- 哪些因子实际被选股器消费；
- AI 因子如何从受限 DSL 进入 candidate、shadow 和人工审批门禁；
- 前端、后端、存储、调度与策略之间如何连接；
- 当前主要限制、阻断点和治理缺口在哪里。

## 2. 交付边界

交付物是线程专属可视化目录中的独立 HTML 片段，由 Codex 会话直接展示。它不写入项目源码，不调用项目 API，不修改数据库、任务、配置或运行服务。

图中内容使用构建时取得的只读证据快照，并明确标注核验时间。它是审计与分析视图，不是实时生产控制台。

本期不包含：

- 编辑节点或连线；
- 启动因子评估、数据同步、研究工厂或交易任务；
- 修改因子参数、选股权重、晋升状态或权限；
- 将可视化嵌入 `FactorPanel`；
- 建设通用 Feature Store 或新因子注册服务。

## 3. 信息架构

### 3.1 端到端主链

首屏默认展开以下横向主链：

`市场与财务数据 → 数据质量门禁 → FactorEngine → 58 个固定因子 → 快照物化 → 全市场评估 → 因子加权选股 → 因子 API → FactorPanel → 策略与 Agent 消费`

主链节点分别回答数据来源、计算、产物、指标、消费和展示问题。主链上的每条边必须标明传递的对象，例如 K 线、财务摘要、因子 DataFrame、快照、评估 JSON、归一化权重或候选股票池。

### 3.2 上方控制链

上方展示跨主链生效的控制与治理节点：

- 数据新鲜度与覆盖率；
- 交易日与固定研究日程；
- 版本、参数、哈希与快照身份；
- 研究任务账本；
- 权限与只读边界；
- 资源消耗与重复计算控制。

控制链使用独立的控制流连线，避免与业务数据流混淆。

### 3.3 下方研究支线

下方展示 AI 因子研究链：

`ResearchTrainingScheduler → 受限 DSL 生成 → 小样本 IC/IR 验证 → promotion state machine → candidate → shadow → 人工审批门禁 → approved loader`

该支线必须清楚表达以下边界：

- DSL 不能执行任意 Python；
- 固定研究调度最高只能晋升到 shadow；
- candidate 和 shadow 不能直接进入生产；
- 生产加载器只接受 approved、健康且数据新鲜的因子；
- AI 因子接入默认关闭。

### 3.4 Qlib 研究支线

Qlib 数据集、质量门禁、模型研究与 shadow signal 作为单独折叠分组展示。该分组与固定 58 因子的公式计算链分开，防止将模型训练误认为固定因子计算的必要环节。

## 4. 画布与节点设计

### 4.1 画布

画布支持拖动、滚轮缩放和双击复位。首屏自动适配端到端主链，避免用户打开后看到空白区域或局部节点。

节点采用分组布局而非自由随机布局，保持稳定的阅读方向：

- 从左到右表示业务处理顺序；
- 从上到下表示控制链、主链、研究支线；
- 相同职责模块保持同一泳道；
- 折叠支线不改变主链的位置。

### 4.2 节点内容

每个节点的紧凑状态包含：

- 节点名称；
- 所属层级或类别；
- 当前状态；
- 一个最关键的指标或日期；
- 输入端口和输出端口。

节点不在画布上堆叠长段说明。详细证据放入右侧详情面板。

### 4.3 连线类型

连线分为四类，并同时使用颜色、线型和文字标签表达含义：

- 数据流：数据或产物的传递；
- 调用流：函数、脚本或 API 调用；
- 控制流：调度、门禁、权限和新鲜度约束；
- 晋升流：candidate、shadow、approved 等状态变化。

任何基于代码推断而非直接提取的关系必须在详情中标记为“推断”，不能显示为已验证事实。

## 5. 状态模型

### 5.1 状态分类

- 绿色“正常”：产物新鲜、覆盖率和质量门禁通过，且上下游链路完整。
- 黄色“受限”：功能可用，但存在固定池、旧评估、局部指标或其他已知限制。
- 红色“阻断”：关键输入不完整、任务账本无成功证据、门禁失败或产物缺失。
- 灰色“未启用”：实现存在，但未取得生产资格或开关关闭。
- 蓝色“基础设施”：中性组件，本身不代表业务有效性。

状态不能依赖单一含糊健康分。全局分析分别呈现：

- 数据质量；
- 计算完整性；
- 评估有效性；
- 选股实际使用；
- 调度闭环；
- AI 因子晋升；
- 前后端可观测性；
- 元数据与版本治理。

### 5.2 状态证据

每个状态必须至少绑定一条具体证据：文件字段、数据库只读查询、运行进程、源码条件或测试契约。状态详情区将信息分为三组：

- 已验证事实；
- 有边界的推断；
- 尚未验证事项。

图中所有运行状态均显示“核验于 2026-08-12 Asia/Shanghai”或更精确的实际采样时间。历史产物自身的生成时间单独显示。

## 6. 详情面板

单击或键盘选择节点后，右侧详情面板展示：

1. 节点职责和业务意义；
2. 输入、输出、直接上游和直接下游；
3. 当前状态、数据日期、覆盖率和关键指标；
4. 对应源码、运行产物及行号；
5. 已验证事实、有边界推断和尚未验证事项；
6. 当前问题及其影响范围；
7. P0、P1、P2 建议；
8. “分析此节点”操作。

“分析此节点”只向 Codex 发出后续分析请求，包含节点名称、证据路径和当前问题；它不调用项目 API 或修改任何状态。

## 7. 交互设计

### 7.1 选择与追踪

- 单击节点：选择节点并高亮直接上下游；
- 再次点击或点击空白：取消选择；
- “追踪全链路”：突出该节点到数据源和最终消费者的完整可达路径；
- 双击画布空白：复位缩放和平移；
- 键盘：使用原生按钮焦点顺序选择节点，不创建自定义 `tabindex`。

### 7.2 分组展开

默认仅完整展开主链。AI 因子、Qlib 和治理支线以分组节点显示，点击后在原泳道内展开内部节点。展开与折叠不能打乱主链阅读顺序。

### 7.3 过滤

提供两组有限过滤，不增加搜索或任意编辑：

- 领域：主链、前端、后端、AI 因子、Qlib、治理；
- 状态：全部、仅异常与受限、未启用。

过滤只改变可见性；被过滤节点的上下游边同步隐藏，不能留下无端点连线。

## 8. 当前证据快照

可视化构建时应纳入以下已核验数据，并在生成前再次读取：

- 固定因子为 19 个技术因子、28 个量价因子、11 个基本面因子，共 58 个；
- 最新常规评估为 5,205 只股票，覆盖 1、5、10、20 日收益和 20 bps 成本；
- 选股器从预设 10 个 `STRONG_FACTORS` 中按方向一致的 1 日 IC 归一化加权，而不是从 58 个因子自由筛选；
- AI 因子通过受限 DSL 生成，并由确定性晋升状态机管理；
- 研究调度器在交易日 16:20 调用因子工厂，最高晋升到 shadow；
- approved loader 仅消费 approved、健康且新鲜的 AI 因子；
- Qlib 六年数据 manifest、研究任务账本、交易日历和中性化评估必须按当前文件重新判定，不能沿用 8 月 10 日审计值。

## 9. 视觉层级

整体采用紧凑的专业节点编辑器视觉：

- 主链节点尺寸一致，核心处理节点略高；
- 状态颜色只用于节点状态标记和关键连线，不给每个节点分配装饰性色；
- 选中节点使用主题主色，异常状态仍保留文字和图形标识；
- 端口使用明确的输入/输出圆点并附短标签；
- 背景保持透明，画布网格使用低对比度主题色；
- 所有文字至少 11 屏幕像素，支持明暗主题。

## 10. 响应式与可访问性

- 主要按 1,024px 宽模式设计，同时支持 736px 和 360px；
- 窄屏时详情面板移动到画布下方，控制项自动换行；
- 画布不使用固定视口高度，避免宿主页面内部滚动冲突；
- 所有节点使用原生按钮，可通过键盘聚焦和激活；
- 状态不只依赖颜色，同时使用文字与形状；
- 画布提供屏幕阅读器摘要，说明当前可见节点数、异常节点数和主链起止点。

## 11. 错误处理

- 证据文件缺失：节点标为红色“阻断”或灰色“未验证”，并显示缺失路径；
- JSON 或 SQLite 读取失败：不使用上次缓存值冒充当前结果；
- 指标字段缺失：显示“未提供”，不默认为 0；
- 某条关系缺乏直接证据：标记为推断或不绘制；
- 可视化脚本异常：首屏仍显示静态节点和文本摘要，不依赖异步网络请求。

## 12. 验证方案

### 12.1 内容验证

- 对照源码与产物检查全部主链节点；
- 检查每条边均有来源、目标、类型和证据；
- 检查 58 因子分类、评估范围、选股因子池、AI 晋升边界与当前状态；
- 检查不存在将 candidate 或 shadow 表述为生产因子的情况；
- 检查历史状态带有时间戳。

### 12.2 交互验证

- 节点选择能更新详情面板；
- 上下游高亮和全链路追踪结果正确；
- 折叠、展开和过滤同步处理节点与连线；
- 缩放、平移和复位均可用；
- “分析此节点”生成包含节点证据的后续请求。

### 12.3 布局验证

- 在 1,024px、736px 和 360px 宽度检查文字、节点、端口、详情和控制项；
- 明暗主题下状态与文字均清晰；
- 不出现连线遮盖标题、文字溢出或空白首屏；
- 所有交互控件均可用键盘访问。

## 13. 完成判定

满足以下条件即视为本次独立全景图完成：

- 图中完整覆盖底层数据、计算引擎、存储、后端、前端、调度、评估、选股、AI 因子工厂和晋升门禁；
- 默认视图清晰呈现端到端业务主链；
- 点击任一核心节点能看到状态、指标、源码证据、影响和分级建议；
- 能从图中明确识别当前正常、受限、阻断和未启用环节；
- 可视化只读且不修改项目或生产状态；
- 交互和响应式验证通过。
