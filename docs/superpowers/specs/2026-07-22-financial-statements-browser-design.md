# 财务报表数据浏览设计

## 目标

在“数据浏览”页面的“实时行情”右侧新增“财务报表”标签。用户输入六位 A 股代码后，页面只读取本地数据库，展示该股票所有 `fin:*:<code>` 财务数据，不触发外部下载。

## 数据边界

- 标准历史数据：`fin:abstract:<code>`，按报告期展示全部字段。
- 来源核验与原始报表：动态读取其余 `fin:*:<code>` 键，包括 `fin:crosscheck:<code>` 及未来新增键。
- 接口不得硬编码仅返回当前已知的两个键。
- 非有限数值转换为空值，确保 JSON 响应合法。
- 股票代码必须规范化为六位数字。

## 页面结构

1. 查询栏：股票代码输入框、查询按钮。
2. 摘要栏：股票名称、报告期数量、数据集数量、最新报告期。
3. 标准历史表：报告期为行，全部指标为列，最新报告期在前，支持横向滚动和粘性表头。
4. 原始数据库数据：按数据键分区；列表对象显示为表格，嵌套对象展开为字段路径和值，确保所有字段可见。
5. 空状态与错误状态：区分代码不合法、数据库无财务数据和接口异常。

## 接口

`POST /api/data`

```json
{
  "action": "financials",
  "code": "600519"
}
```

返回：

```json
{
  "success": true,
  "data": {
    "code": "600519",
    "name": "贵州茅台",
    "keys": ["fin:abstract:600519", "fin:crosscheck:600519"],
    "datasets": {},
    "history": [],
    "history_count": 102,
    "latest_report_date": "20260331"
  }
}
```

## 安全与性能

- `financials` 为只读动作，不需要控制权限。
- 单次只读取一只股票的精确后缀键。
- 页面不轮询，只有首次进入和用户查询时请求。
- 大表使用滚动容器，不一次生成额外图表或复制数据。

## 验证

- 后端测试覆盖动态键、非法代码、NaN 清理和空数据。
- 前端契约测试覆盖标签顺序、组件挂载和接口动作。
- 生产构建通过。
- 浏览器验证输入代码、查询成功、全部区域渲染、无控制台错误。
