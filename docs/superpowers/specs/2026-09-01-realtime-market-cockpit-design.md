# XuanJiQuant 准实时行情与驾驶舱盯市设计

日期：2026-09-01

## 1. 目标与完成判定

本设计解决三个相互关联的问题：市场浏览更新慢、实时行情轮询得到重复缓存、投资驾驶舱权益与风险停留在首次盘中执行快照。

完成必须同时满足：

1. 盘中热证券行情端到端新鲜度 p95 不高于 2 秒；热证券包括 F5 持仓、自选股、当前查看证券和页面可见证券，总订阅上限 200 只。
2. 全市场成交额/成交量 Top100 使用完整市场快照，快照新鲜度 p95 不高于 12 秒；不得用部分批次冒充全市场排名。
3. 驾驶舱总权益、今日盈亏、持仓市值和组合风险在盘中随可信行情更新，新鲜度不高于 3 秒。
4. 驾驶舱初始关键指标响应 p95 不高于 300 毫秒；系统健康、外部情绪和研究组合不得继续阻塞账户首屏。
5. 无论连接多少浏览器页面，同一热证券集合只产生一条上游刷新循环；不得出现请求重叠或每客户端独立抓取。
6. 盯市只能更新价格、估值和风险事实，不能写订单、成交、现金、数量、成本、策略组合或执行权限。
7. 行情过期、来源失败、休市或 SSE 断开时必须明确显示状态；缓存值不得标记为实时。
8. 所有当前账户事实继续归属于 `data/paper/f5_ledger.db`，不得回退到 `execution:state`、旧订单/成交表或历史持仓快照。

## 2. 非目标与权限边界

- 不连接真实券商，不增加实盘权限，`live_execution_authority=false` 固定不变。
- 不改变 F4、Qlib、研究组合、硬风控阈值或 F5 交易准入条件。
- 不把页面刷新变成交易执行，不允许客户端提交价格、数量、方向或证券作为 F5 盯市写入事实。
- 不宣称交易所逐笔级实时。现有 TdxQuant/新浪/腾讯属于轮询式 Level-1 数据；本设计交付的是在现有数据源能力内的 1–2 秒准实时热行情。
- 不对 5200 余只股票做 1 秒全市场刷新。全市场快照保持完整性优先，使用 8–10 秒后台周期。
- 不新增第三方前端依赖；SSE 使用 Node HTTP 和浏览器原生 `EventSource`。

## 3. 已验证基线

2026-09-01 现场证据：

- 市场浏览前端每 15 秒调用 `stocks`，后端 Top100 TTL 为 20 秒；一次完整全市场刷新约 10 秒，有效新鲜度约 15–30 秒。
- 实时行情前端每 5 秒调用 `realtime_prices`，后端视图 TTL 为 15 秒、逐代码缓存 TTL 为 120 秒；大部分轮询重复读取同一快照。
- 15 只证券的缓存读取为 7–11 毫秒，强制真实行情获取约 420 毫秒，证明热证券 1 秒级单飞刷新可行。
- Top100 缓存读取为 18–156 毫秒；后台完整刷新后约 10 秒切换为 `realtime`。
- 驾驶舱没有自动轮询；点击“刷新”只重新请求 `workbench status`。
- 驾驶舱组合接口连续两次耗时 3.65–3.76 秒。分项中 `system_health` 约 3.10 秒、F5 `status` 约 1.47 秒、F5 `account` 约 644 毫秒、组合风险约 434 毫秒。
- 2026-09-01 的唯一 F5 运行、权益快照和 15 个持仓价格均停在 09:35:16；后续每 5 分钟任务因交易幂等没有产生新的盯市事实。

根因不是网络请求本身慢，而是刷新所有权分散、缓存周期与前端轮询不一致、全市场刷新与热行情共用请求路径、驾驶舱把慢诊断放入关键路径，以及交易运行幂等被错误复用于账户盯市。

## 4. 总体架构

采用“热行情、全市场快照、F5 盯市、页面推送”四条职责明确的链路：

```text
TdxQuant（主）/ 新浪腾讯（降级）
  |
  +-> HotQuoteLoop（1 秒，最多 200 只，单飞）
  |     -> quant.db 统一逐代码行情缓存
  |     -> F5 mark_to_market（无客户端价格参数）
  |     -> SSE hot_quotes / cockpit_mark
  |
  +-> FullMarketSnapshotLoop（8–10 秒，5200+只，单飞）
        -> 完整快照原子切换
        -> 内存排序 Top100
        -> SSE market_top100

浏览器
  -> 首次 REST 快照
  -> EventSource 增量事件
  -> 断线后有界退避重连
  -> SSE 不可用时自适应轮询降级
```

交易执行与盯市保持分离：

```text
F5 execution run key -> 保证订单/成交每日幂等
F5 market mark key   -> 按行情批次更新估值，不生成订单
```

## 5. 热行情中心

### 5.1 进程与所有权

Node API 进程新增单例 `MarketStreamService`。它维护浏览器订阅集合，并通过独立的持久 Python `data_runner.py` 请求通道获取热行情，避免全市场刷新阻塞热行情请求。服务启动和停止跟随现有 API 生命周期，不新增常驻计划任务。

订阅集合为以下并集：

- F5 当前持仓代码，服务端固定加入；
- 浏览器自选代码；
- 当前选中股票；
- 当前可见表格代码。

所有代码在服务端归一化和去重，最多 200 只。超过上限时优先级为 F5 持仓、当前选中、自选、可见表格；超出部分返回明确的 `subscription_truncated` 状态。

### 5.2 刷新节奏

- A 股连续竞价时段：每 1 秒尝试一次热行情批量刷新。
- 午间休市：每 15 秒核对一次状态，不强制重复获取静态价格。
- 收盘后：每 60 秒读取最后收盘事实；页面显示“已收盘”，不显示“实时”。
- 页面全部断开时仍保留 F5 持仓集合；无持仓且无客户端时暂停热循环。

刷新使用单飞锁：前一轮未结束时跳过本轮，不排队。单轮硬超时 800 毫秒；连续三次失败进入降级状态并使用最后可信快照，随后按 2、5、10 秒有界退避恢复。

### 5.3 行情真实性

每个行情事件必须包含：

- `code/name/price/prev_close/high/low/volume/amount`；
- `quote_timestamp/source/source_volume_unit`；
- `received_at/snapshot_id`；
- `stale/age_ms/market_phase`。

盘中 `quote_timestamp` 缺失、不是当前交易日、未来漂移超过 5 秒、价格非正或批次身份不一致时，该证券不得标记为实时。部分证券失败可保留旧值，但必须逐证券标记 stale；不得把部分批次用于全市场 Top100。

## 6. 全市场 Top100 快照

全市场快照继续由 `data_runner.py` 负责，保留 TdxQuant 主源和现有降级链，但从页面触发改为后台固定周期。

- 目标周期 8 秒；若一轮耗时超过周期则下一轮紧接终态开始，永不并发。
- 快照只有在活动股票池全部批次完成并通过最低覆盖门槛后才原子切换。
- 最低覆盖门槛沿用当前可接受全市场口径；覆盖不足时保留上一完整快照并显示缺口。
- Top100 排序从完整快照内存完成，不再为金额、成交量排序分别抓取市场。
- `refreshing` 表示后台是否正在构建下一代，已完成快照本身不得永久携带 `refreshing=true`。
- 前端打开市场浏览时立即得到上一完整快照；新一代完成后由 SSE 推送替换，无需等待下一次 15 秒轮询。

## 7. F5 独立盯市

### 7.1 新账本事实

在唯一 F5 数据库中增加：

1. `paper_live_marks`：每个持仓代码一行，保存最新可信价格、来源、行情时间、快照身份和接收时间。
2. `paper_live_account`：单例当前估值，保存现金、持仓市值、总权益、今日盈亏、未实现盈亏、持仓数、行情批次身份、估值时间和过期状态。

现有 `paper_equity_snapshots` 继续作为历史曲线，但只在以下条件之一满足时追加：

- 距上次历史快照至少 30 秒；
- 发生订单/成交；
- 市场阶段切换；
- 当日最后一个有效收盘快照。

因此高频盯市不会每秒扩张历史表，但当前估值始终留在 F5 权威账本内。

### 7.2 固定盯市动作

F5 runner 增加无业务参数的 `mark_to_market` 固定动作：

1. 从 F5 账本读取当前持仓代码；
2. 从统一行情缓存读取对应的最新可信快照；
3. 校验交易日、时间、来源、价格和批次身份；
4. 在单个 SQLite 事务内更新 `paper_live_marks` 与 `paper_live_account`；
5. 按 30 秒规则追加历史权益快照；
6. 返回估值身份和新鲜度。

客户端不得提交代码、价格、数量、方向、日期或现金。任何额外业务字段均拒绝。该动作不调用下单、撮合、对账或策略选择代码。

### 7.3 今日盈亏定义

今日盈亏固定为：

`当前实时总权益 - 上一交易日最后一个有效权益`

若没有上一交易日权益，则使用当日首个有效估值作为基线并标记 `daily_pnl_baseline=first_mark`；不得显示伪造的 0 或沿用不相关历史账户。

### 7.4 并发与失败

- 盯市写事务与执行写事务共享 F5 SQLite WAL 和有界忙等待。
- 执行正在提交订单/成交时，盯市本轮跳过并在下一秒恢复，不修改执行租约。
- 行情过期时不覆盖最新可信价格，只更新 `stale=true` 和原因。
- 任意盯市失败只影响估值新鲜度，不能触发交易恢复态、熔断或策略降级。

## 8. 风险与驾驶舱快路径

### 8.1 快慢数据拆分

驾驶舱初始 REST 状态只等待：

- F5 `paper_live_account` 与持仓；
- 基于同一估值批次的组合风险；
- 自动模拟当前只读许可摘要。

以下慢数据从关键路径移出：

- 系统健康：后台每 10 秒刷新缓存；
- 研究目标组合：按研究 generation 身份缓存，最长 30 秒；
- 外部情绪：沿用来源自身新鲜度，不阻塞账户；
- 完整 F5 readiness：按证据身份缓存 2 秒，变化时主动失效。

首次状态响应可携带上一份慢诊断和其时间戳；没有缓存时显示“诊断加载中”，不得等待 3 秒健康检查。

### 8.2 风险一致性

风险计算必须绑定 `market_snapshot_id` 和 `valuation_as_of`。综合风险仍使用现有确定性规则和阈值；本设计只更新输入价格和计算频率，不改变风险等级算法。

驾驶舱分别显示：

- `行情时间`：上游 quote timestamp；
- `权益估值时间`：F5 live account committed_at；
- `风险计算时间`：risk calculated_at；
- `数据状态`：实时、延迟、休市、降级或不可用。

盘中任一关键时间超过 3 秒，界面必须显示黄色“行情延迟”；超过 15 秒显示红色“实时估值不可用”，并保留最后可信数值及其时间。

## 9. SSE 协议与前端行为

### 9.1 接口

新增仅限本机只读的 GET SSE 路由。连接必须来自允许的本机 Origin；不在 URL 中传递 API token。

事件类型：

- `hot_quotes`：热证券行情批次；
- `market_top100`：完整 Top100 快照；
- `cockpit_mark`：F5 实时权益与快速风险；
- `stream_status`：连接、市场阶段、延迟和降级状态；
- `heartbeat`：15 秒心跳，供断线检测。

事件包含单调递增序号和 snapshot id。前端忽略重复或倒序事件。

### 9.2 页面

新增共享 `useMarketStream` hook：

- 数据浏览订阅 `market_top100`；
- 实时行情订阅自选和可见代码的 `hot_quotes`；
- 驾驶舱订阅 `cockpit_mark`；
- 页面首次加载仍通过 REST 获取完整快照，SSE 只传增量；
- 页面不可见时减少订阅并停止非必要渲染；
- 断线使用 1、2、5、10 秒退避重连；30 秒无法恢复时启用轮询降级。

降级轮询频率：热行情 2 秒、Top100 5 秒、驾驶舱 2 秒；轮询仍使用后端单飞缓存，不直接形成每客户端上游请求。SSE 恢复后立即停止轮询。

价格闪烁只更新变化行，使用批量状态提交，避免整个 100 行表格每秒重渲染。

## 10. 性能与资源约束

- 热行情单轮最多 200 只，目标 800 毫秒内完成。
- 同时 10 个浏览器客户端时，上游热行情调用次数不得超过单客户端时的 1.1 倍。
- Top100 构建与热行情使用独立持久 runner；慢全市场任务不得阻塞热行情事件。
- 所有定时循环都有重叠保护、超时、退避和关闭清理。
- SSE 每连接设置发送缓冲上限；慢客户端丢弃中间行情事件，只保留最新批次，禁止无限排队。
- F5 live mark 每秒最多一次事务；历史权益最多每 30 秒一条，执行事件除外。
- 工作台慢诊断缓存必须带证据时间，缓存不可伪装为最新计算。

## 11. 配置与默认值

配置集中在受治理的服务配置中，不允许前端任意放宽：

- `hot_quote_interval_ms=1000`
- `hot_quote_timeout_ms=800`
- `hot_quote_max_symbols=200`
- `hot_quote_stale_ms=3000`
- `full_market_target_interval_ms=8000`
- `cockpit_risk_interval_ms=2000`
- `equity_history_interval_ms=30000`
- `system_health_cache_ms=10000`
- `research_selection_cache_ms=30000`
- `sse_heartbeat_ms=15000`

测试环境允许通过依赖注入缩短时间，不读取前端提交的频率参数。

### 11.1 全功能同步矩阵

“最大化同步”按数据事实的产生频率定义，禁止把静态或低频事实伪装成实时。统一同步目录必须登记数据集、所有者、主源/降级源、活动/后台周期、最近成功时间、事实时间、覆盖率、过期阈值、当前状态和失败原因。

| 数据域 | 活动周期 | 后台/休市周期 | 事实边界 |
|---|---:|---:|---|
| F5持仓/自选/当前可见热行情 | 1秒 | 午间15秒、收盘后60秒 | 准实时Level-1 |
| 全市场完整快照与Top100 | 8秒目标、完成即切换 | 收盘后60秒 | 只发布完整代 |
| 当前股票逐笔/盘口展示 | 5秒 | 页面不可见时暂停 | 来源支持范围内 |
| 驾驶舱权益盯市 | 行情批次完成即更新，最多1秒一次 | 收盘后固定终态 | F5唯一账本 |
| 组合风险 | 2秒 | 休市60秒 | 绑定同一估值批次 |
| 核心指数/宏观行情 | 10秒 | 60秒 | 来源时间戳必须可见 |
| 金十快讯 | 30秒 | 90秒 | 增量合并、不得重复 |
| 新闻资讯 | 60秒 | 5分钟 | 来源时间戳与缓存状态 |
| 财经日历 | 5分钟 | 15分钟 | 事件更新而非价格流 |
| 巨潮最新公告/业绩公告 | 活动页面60秒 | 后台5分钟 | 公告发布时间 |
| 财务报表/估值基本面 | 盘后一次并在新公告后触发 | 每日完整性核对 | PIT披露时间 |
| 1分钟K线 | 每个闭合分钟后更新 | 休市停止 | 未闭合K线不得进日线 |
| 日K/股票池 | 收盘后确定性日更 | 失败按同幂等任务重试 | 完整交易日 |
| 因子评估/研究选股 | 日线完整代提交后日更 | 不轮询重算 | 同一数据版本 |
| F4策略验证 | 周频及公共证据补偿触发 | 不因页面访问启动 | 样本外研究 |
| Qlib研究 | 周/月/季固定日程 | 不因F4或页面访问启动 | 独立研究账本 |
| 告警评估 | 5秒消费最新状态 | 休市60秒 | 不触发交易 |
| 系统健康 | 10秒后台缓存 | 30秒 | 不阻塞业务首屏 |

统一调度必须遵守：单飞、页面可见性降频、来源限流、超时、熔断、最后可信值、明确 stale、恢复后立即补一次、进程退出时清理定时器。任何页面不得私自设置比目录更高的上游抓取频率；多个页面只能共享服务端同步结果。

## 12. 可观测性

服务状态至少公开：

- 热订阅证券数、客户端数、循环状态；
- 上次成功/失败时间、上游延迟、快照年龄；
- 单飞跳过次数、超时次数、降级来源；
- Top100 generation、覆盖数、构建耗时；
- F5 mark batch id、估值时间、持仓覆盖率；
- SSE 发送事件数、重连数、慢客户端丢弃数；
- 驾驶舱快路径和慢诊断分项延迟。

日志不得包含 API token、完整请求头或外部凭据。

## 13. 测试策略

实施采用测试驱动开发，至少覆盖：

1. 热行情单飞：并发客户端只能触发一个上游刷新。
2. 订阅优先级与 200 只上限。
3. 行情时间、交易日、价格和批次身份校验。
4. 部分证券失败时逐证券 stale，不污染成功证券。
5. Top100 仅从完整快照原子切换，排序正确，完成后 `refreshing=false`。
6. `mark_to_market` 拒绝任何客户端业务参数。
7. 盯市前后订单、成交、现金、数量、成本哈希不变。
8. 盯市更新总权益、今日盈亏、当前价格和风险输入。
9. 执行事务与盯市事务并发时无重复订单、无丢失成交、无数据库锁死。
10. 历史权益 30 秒节流与执行事件例外。
