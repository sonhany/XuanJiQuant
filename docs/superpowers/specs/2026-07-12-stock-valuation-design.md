# 股票估值功能设计

## 1. 目标

在“数据浏览”中新增独立的“股票估值”页面，为单只 A 股提供四条相互独立、
可解释、可审计的估值结果：

1. 绝对估值。
2. 相对估值。
3. 市场估值。
4. GLM 模型估值。

估值功能属于研究辅助工具，不直接生成订单，不绕过 verifier 或 risk gateway，
不修改模拟盘或实盘配置。

## 2. 用户入口

### 2.1 数据浏览导航

“数据浏览”二级导航调整为：

1. 市场浏览。
2. 股票估值。
3. 实时行情。
4. K线走势。
5. 数据管理。

“股票估值”页面支持输入股票代码或名称。进入页面后自动计算规则估值，
GLM 估值由用户点击触发。

### 2.2 Top100 右键菜单

“市场浏览”Top100 股票右键菜单新增“股票估值”：

- 点击后关闭菜单。
- 自动将股票代码和名称传入估值页面。
- 跳转到“股票估值”Tab。
- 自动运行绝对估值、相对估值和市场估值。
- 不自动调用 GLM。

原有“AI 委员会分析”“K线走势”“加入自选股”保持不变。

## 3. 页面结构

采用研究工作台布局。

### 3.1 顶部操作区

- 股票代码或名称输入框。
- “重新估值”按钮。
- “运行 GLM 估值”按钮。
- 当前股票代码和名称。
- 数据刷新状态及错误提示。

### 3.2 首屏摘要

并列展示：

- 最新价。
- 绝对估值中枢。
- 相对估值中枢。
- 市场估值中枢。
- GLM 估值中枢。

每项同时显示数据日期、状态或置信度。未计算或不可用时显示明确原因，
不使用零值伪装有效结果。

### 3.3 四类估值结果

每类估值使用独立区域展示：

- 保守、中性、乐观价格或目标区间。
- 当前价格对应的安全边际。
- 核心参数和计算口径。
- 数据覆盖范围。
- 数据完整度。
- 模型状态及降级原因。

### 3.4 财务和审计区

展示：

- 营收增长。
- 利润增长。
- ROE。
- 经营现金流。
- 资本开支。
- 负债率。
- Beta。
- WACC。
- 敏感性矩阵。
- 行情日期和财务报告期。
- 数据来源、缺失字段和交叉校验警告。
- 公式版本、模型版本和 prompt 版本。

## 4. 后端架构

### 4.1 API

新增 `/api/valuation`，使用 JSON POST：

- `analyze`：执行三类确定性估值。
- `glm_analyze`：调用 GLM 独立估值。
- `latest`：读取最近一次估值结果。

API 对股票代码做严格白名单校验，仅接受合法 A 股代码，并继续排除 920xxx。

### 4.2 Runner

新增 `scripts/valuation_runner.py`，使用项目现有 `PersistentRunner` 模式，
负责请求解析、结果编排、缓存读取和结构化响应。

不把估值逻辑继续堆入 `scripts/data_runner.py`。

### 4.3 估值模块

新增 `quant/valuation/`：

- `absolute.py`：FCFF/DCF 计算和敏感性分析。
- `relative.py`：同行样本选择及 PE/PB/PS/PEG 隐含价格。
- `market.py`：历史、行业、指数、流动性和风险偏好综合定价。
- `glm.py`：GLM 输入协议、输出 Schema 和边界检查。
- `service.py`：数据读取、完整性判断、缓存、编排和持久化。
- `contracts.py`：统一请求和响应结构。

各模块只负责单一估值职责，可单独测试。

## 5. 数据来源

### 5.1 行情

遵循现有数据策略：

- TdxQuant 优先。
- 新浪和腾讯兜底。
- 优先读取数据库最新结果。
- 数据过期时后台刷新。

### 5.2 财务

使用项目结构化财务数据，按以下顺序读取：

1. 数据库最新有效财务记录。
2. TdxQuant 可用财务字段。
3. AkShare 财务摘要和财务分析指标。
4. 其他已配置交叉验证源。

每个字段保留来源和报告期，不把不同报告期数据无提示混合。

### 5.3 同行与市场样本

- 行业分类优先读取 TdxQuant 分类数据。
- 同行业样本按规模、主营和数据完整度筛选。
- 排除 ST、退市、920xxx、负净资产和对应倍数无效的股票。
- 极端倍数通过分位缩尾或 IQR 规则剔除。
- 个股历史估值使用实际可用范围；不足三年时必须标明覆盖期。

## 6. 绝对估值

采用 FCFF/DCF，输出保守、中性和乐观三档。

### 6.1 现金流

优先使用：

`FCFF = 经营现金流 - 资本开支`

字段完整时可使用：

`FCFF = EBIT × (1 - 税率) + 折旧摊销 - 资本开支 - 营运资本增加`

禁止用净利润直接冒充自由现金流。核心字段不足时返回 `unavailable`。

### 6.2 预测参数

- 预测期默认五年。
- 增长率根据历史营收、利润和现金流推导并限制异常范围。
- 永续增长率限制在 `0%–3%`。
- Beta 根据个股和基准指数历史收益计算。
- WACC 根据无风险利率、Beta、市场风险溢价、债务成本和资本结构计算。

### 6.3 输出

- 企业价值。
- 股权价值。
- 每股价值。
- 三种情景价格。
- WACC/永续增长敏感性矩阵。
- 参数来源和完整度。

## 7. 相对估值

分别计算：

- PE 隐含价格。
- PEG 隐含价格。
- PB 隐含价格。
- PS 隐含价格。

仅在对应指标有效时参与结果。最终展示各方法结果和基于有效方法中位数形成的区间，
不把负 PE 或负净资产样本强行纳入。

输出同行样本数、剔除数、行业中位数、目标公司分位和样本代码列表。

## 8. 市场估值

市场估值综合以下信息：

- 个股历史 PE/PB/PS 分位。
- 所属行业估值分位。
- 沪深300等主要指数估值状态。
- 市场宽度。
- 全市场成交活跃度。
- 风险偏好和流动性状态。

输出市场状态：

- 折价。
- 中性。
- 溢价。

并输出市场环境下的保守、中性和乐观价格区间。所有调整因子必须有固定上限，
防止单一市场指标过度放大估值。

## 9. GLM 模型估值

GLM 接收结构化输入：

- 三类规则估值结果。
- 最新财务指标。
- 当前行情和历史波动。
- 行业位置。
- 市场状态。
- 数据缺失和交叉验证警告。

GLM 使用严格 Schema 返回：

- 目标价格下限。
- 目标价格中枢。
- 目标价格上限。
- 置信度。
- 核心假设。
- 上涨驱动。
- 下行风险。
- 估值失效条件。
- `model_version`。
- `prompt_version`。

GLM 结果独立展示，不与规则估值自动加权，不覆盖前三类结果，不生成订单。
JSON 解析失败、字段缺失、数值越界或置信度非法时直接废弃。

## 10. 缓存与审计

估值缓存键由以下字段构成：

- 股票代码。
- 行情数据日期。
- 财务报告期。
- 公式版本。
- 参数签名。

GLM 缓存还包含模型版本和 prompt 版本。

新增结构化 `stock_valuations` 表，保存：

- 股票代码和名称。
- 估值类型。
- 输入快照。
- 输出结果。
- 数据来源。
- 数据日期和报告期。
- 状态和错误。
- 公式、模型及 prompt 版本。
- 创建时间。

GLM 调用继续写入现有 `model_calls`；估值执行同时写入 `audit_events`。

## 11. 异常和降级

- 各估值模型独立返回 `success`、`partial`、`unavailable` 或 `error`。
- 单项失败不影响其他模型展示。
- 数据过期时显示警告并触发后台刷新。
- 财务字段缺失时显示缺失字段，不生成伪精确价格。
- GLM 超时、限流或格式错误不影响规则估值。
- API 返回可读错误，不向前端暴露堆栈、密钥或原始敏感配置。

## 12. 性能

- 页面进入后并行读取行情、财务、行业和历史数据，避免串行瀑布。
- 规则估值缓存命中目标响应时间小于 500ms。
- 首次规则估值目标响应时间小于 5s，不包含外部数据补拉时间。
- GLM 独立异步调用，不阻塞规则结果展示。
- 页面不自动轮询 GLM。

- Runner 超时和错误响应。
- 控制面鉴权要求。

### 13.3 前端

- “股票估值”Tab 位于“市场浏览”后。
- 输入股票后展示四类估值。
- Top100 右键菜单可跳转并带入股票。

- 单项不可用不导致白屏。

## 14. 非目标

- 不提供买卖指令或自动仓位建议。
- 不将 GLM 目标价直接送入交易执行。
- 不承诺估值结果等于未来市场价格。
- 本阶段不实现全市场自动批量 GLM 估值。
