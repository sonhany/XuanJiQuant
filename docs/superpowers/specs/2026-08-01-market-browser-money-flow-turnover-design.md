# 市场浏览个股资金流与换手率设计

日期：2026-08-01  
状态：待用户复核

## 1. 目标

在“市场数据 → 数据浏览 → 市场浏览”的现有成交额 Top100 股票表格中增加：

- 换手率（`turnover_rate`，单位 `%`）
- 主力净流入额（`main_net_inflow`，单位元；正数为净流入，负数为净流出）
- 主力净流入占比（`main_net_inflow_pct`，单位 `%`）

改造必须保留现有 TdxQuant 优先的实时行情链路、成交额 Top100 排名口径、15 秒前端轮询、Python 常驻 runner 和只读 API 边界。资金流补充失败不得阻断原有股票列表。

## 2. 当前架构与调用关系

```text
components/DbPanel.tsx
  -> POST /api/data { action: "stocks", limit: 100, sort_by: "amount" }
  -> server/router.mjs（只读动作白名单）
  -> server/routes/data.mjs（data-stocks PersistentRunner）
  -> scripts/data_runner.py::action_stocks
  -> scripts/data_runner.py::_top_realtime_stocks
  -> scripts/market_data.py::fetch_realtime
       -> quant/data/tdx_quant_source.py（实时行情主源）
       -> quant/data/tencent_source.py（成交额及行情降级）
       -> 新浪实时行情（最终降级）
  -> 按成交额排序并截取 Top100
  -> 返回 DbPanel 展示、排序及 CSV 导出
```

Node 层只负责路由、权限和 Python 进程协议，不解析或拼装行情业务字段。数据源解析和字段来源必须留在 Python 数据层。

## 3. 方案选择

采用“现有行情主链 + Top100 批量字段补充”。不将市场榜单整体切换为东方财富，也不让前端直接请求外部数据源。

原因：

1. 保留 TdxQuant 主源与现有成交额排名，避免改变已有业务口径。
2. 仅对已经选出的 Top100 请求补充字段，避免全市场重复抓取。
3. 外部数据源、缓存、解析和降级均封装在 Python 数据层，前端只消费稳定字段。
4. 不新增路由、不修改 SQLite 表结构、不影响交易、风控、因子或 Qlib 模块。

## 4. 后端设计

### 4.1 东方财富批量补充

在 `scripts/market_data.py` 增加独立的个股市场指标批量函数。输入标准六位股票代码，按有界批次调用东方财富 `https://push2delay.eastmoney.com/api/qt/ulist.np/get` 批量列表接口，读取：

联调证据：`push2.eastmoney.com` 的同路径在本机网络会被远端主动断开，`push2delay.eastmoney.com` 可稳定返回相同字段。因此实现固定使用延迟域名，并用契约测试保护该可达端点。

| 上游字段 | 项目字段 | 口径 |
|---|---|---|
| `f8` | `turnover_rate` | 换手率，百分数 |
| `f62` | `main_net_inflow` | 主力净流入额，元 |
| `f184` | `main_net_inflow_pct` | 主力净流入占比，百分数 |

仅接受有限数值。上游缺失、`null`、非数值或异常值映射为 `None`，不能映射为零。每行补充 `money_flow_source="eastmoney"`；批次请求使用短周期缓存并设置明确超时。

### 4.2 腾讯换手率降级

`quant/data/tencent_source.py` 当前只解析到实时行情字段 37。扩展解析字段 38 为 `turnover_rate`，但不改变既有价格、成交量、成交额和时间字段。

东方财富没有返回某只股票的换手率时，可使用腾讯换手率；此时该行的换手率来源为腾讯。腾讯不提供本改造所需的主力净流入口径，因此不能用估算值补主力资金字段。

### 4.3 Top100 合并位置

在 `scripts/data_runner.py` 中，仅在现有排序和 `limit` 截取完成后调用补充函数，再按股票代码合并：

```text
实时行情全市场候选
  -> 现有 amount/volume 排序
  -> 现有 limit 截取
  -> 批量补充换手率和主力资金
  -> 返回
```

实时主路径、日摘要加实时补全路径和最终 K 线降级路径应通过同一个小型合并函数复用规则，避免三处分叉实现。

补充请求发生异常时捕获异常并记录 debug/warn 级别来源信息，原有股票数据照常返回；新增字段为 `None`。不得因东方财富失败返回 500，也不得改变股票排序。

## 5. 前端设计

修改 `components/DbPanel.tsx`，在既有 `Stock` 类型和规范化逻辑中保留新增字段：

- 在“振幅”后增加“换手率”“主力净流入”“主力净占比”。
- 三列支持现有前端升降序排序。
- 主力净流入和净占比：正数红色、负数绿色、零值中性色。
- 缺失值显示 `--`；真实零值显示 `0.00`，两者不得混淆。
- 金额沿用现有万/亿紧凑格式；百分比保留两位小数。
- CSV 同步增加三列，导出原始数值，便于后续分析。
- 表格容器增加横向滚动和最小宽度；打开右侧逐笔详情时不压缩字段内容。
- 市场浏览状态文字标注“行情：现有主链；资金流：东方财富；换手率：东方财富/腾讯降级”，说明字段可能来自不同数据源。

## 6. 缓存、性能与审计

- Top100 原有缓存键和 TTL 保持不变。
- 新增补充数据使用独立缓存键，不把外部补充失败写成有效零值。
- 批次大小有明确上限，防止 URL 过长；最多覆盖本次返回的 `limit` 只股票。
- 响应保留每行来源字段，并在顶层增加补充数据抓取时间或状态摘要，方便排查陈旧数据。
- 不写入 `data/quant.db`，不修改行情历史、交易账本或 Qlib 仓库。

## 7. 测试策略

按测试驱动顺序实施：

1. Python 先写失败测试：东方财富字段解析、缺失值、代码映射、分批、缓存和异常降级。
2. Python 先写失败测试：Top100 排序不变，补充字段只在截取后合并；东方财富失败仍返回原列表。
3. Python 先写失败测试：腾讯字段 38 解析为换手率，不影响现有字段。
4. Node 契约先写失败断言：三列、规范化、排序、缺失展示、颜色、CSV 和来源说明存在。
5. 最小实现使新增测试通过，再运行现有数据源、数据浏览、TypeScript 和 Vite 构建验证。
6. 对运行中的 `/api/data action=stocks` 做只读请求，核对字段、来源和 Top100 成交额降序不变。
7. 浏览器验证市场浏览页面在全宽和打开逐笔详情两种布局下均可用。
