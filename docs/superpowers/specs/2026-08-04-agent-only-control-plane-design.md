# Agent 唯一控制平面设计

日期：2026-08-04

## 1. 目标

XuanJiQuant 的自动化交易控制平面只保留 Agent Runtime。删除旧 AI 循环的代码、调度分支、执行入口、配置选项、回退机制、控制接口、界面状态和当前文档，不保留可重新启用的兼容壳。

本次切换仍限定在模拟盘。它不会开放实盘或券商自动下单，也不会降低确定性硬风控、验证器、执行会话、围栏令牌、订单幂等和人工熔断要求。

## 2. 完成标准

切换完成后必须同时满足：

1. `scripts/ai_loop.py` 及旧循环专用测试被删除，仍有价值的通用分析能力迁入职责明确的 Agent 模块。
2. 调度器不存在旧周期、双跑、影子对比旧控制器或自动回退旧控制器的分支。
3. 执行所有权不再是二选一配置；自动化执行者固定为 Agent Runtime。
4. Agent 故障、证据不足、调度超时或数据过期时失败关闭，不新增仓位，并给出准确中文原因。
5. API、Web、Runner、数据库当前状态和交接文档不再把旧 AI 暴露为可选状态或操作目标。
6. 源代码、活动配置、活动数据库约束、构建产物和当前文档中不存在旧控制器标识；历史交易、订单、风控和审计事实不伪造、不删除。
7. 定向测试、Python 全量测试、Node 契约、TypeScript、Vite 构建、Python 冒烟和实际 Web/API 请求全部通过。

## 3. 新架构

唯一自动化调用链为：

```text
AI Scheduler
  -> Agent Runtime（研究 / 复盘 / 执行）
  -> Agent Store（Run、工具调用、验证结果、发布凭证）
  -> Verified Decision Publication
  -> Paper Trader（仅接受绑定的 Agent 执行会话）
  -> Deterministic Risk Gateway
  -> Execution Ledger（模拟盘）
```

独立安全链为：

```text
行情与宏观采集 -> 时效性判定 -> 风险输入
账户与持仓     -> 组合风险     -> 风险输入
告警与熔断     -> 硬阻断       -> 风险输入

任一输入不可确认 -> 失败关闭 -> 暂不新增仓位
```

Agent 负责读取证据、调用工具、形成目标组合、解释判断并提交可验证决策。它不能绕过风险网关，也不能自行扩大权限。

## 4. 控制权与降级语义

### 4.1 唯一所有者

- 删除 `execution_owner` 的多所有者选择语义。
- 自动化执行会话的 actor/source 只接受 `agent_runtime`。
- 人工操作只保留停止、取消、强制减仓和维护权限，不成为第二个自动化 AI 控制器。
- 当前运行模式迁移为 `paper_guarded`；研究与复盘 Run 始终没有执行资格。

### 4.2 不再回退旧 AI

原有的自动回退、人工回退和旧 owner handoff 全部删除。Agent 连续失败、调度卡死或状态冲突时执行：

1. 停止产生新的执行型 Run；
2. 使未消费的执行会话失效；
3. 保留取消订单和风险降低能力；
4. 状态切换为“维护中/失败关闭”；
5. 要求人工排障后重新启用 Agent。

### 4.3 数据库迁移

执行权表迁移为 Agent-only schema。迁移时先停止 AI Scheduler 和模拟盘执行入口，确认没有活动 Run、未完成会话、pending/partial 订单或未知副作用，再执行事务化迁移并提升 owner epoch/fencing token。

活动状态中所有旧控制器字段必须消失。历史交易、订单、风控及审计事件属于真实业务事实，不做机械篡改；它们只能由只读审计查询访问，不能参与运行态解析、默认值或回退。

## 5. 模块调整

### 5.1 删除

- `scripts/ai_loop.py`
- `scripts/ai_scheduler.py` 中旧周期、双跑和旧回退分支
- `scripts/ai_action_executor.py` 中旧执行授权与旧 paper 入口
- `scripts/paper_trader.py` 中旧 context、旧 source 和公共旧执行入口
- `scripts/paper/decision_reader.py` 中非 Agent 决策路径
- `quant/agent/control.py` 中回退旧控制器的动作和确认口令
- `quant/agent/policies.py` 中旧 owner、handoff target、旧 session source 和旧默认值
- Server/API/Web 中旧状态、旧按钮、旧中文映射和旧控制动作
- 仅验证旧循环或双控制器行为的测试、过时设计文档和过时实施计划

### 5.2 保留并整理

- Agent Runtime 的 Run 状态机、工具白名单、验证器和发布凭证
- Agent Store、执行会话、围栏令牌、订单幂等与执行账本
- 确定性组合风险、宏观风险、熔断和人工紧急控制
- 仍有业务价值的选股、组合构建和研究能力，但迁入 Agent 专属模块，不允许继续依赖已删除文件

### 5.3 新增边界

- Agent-only policy：固定控制器、允许模式、失败关闭状态
- Agent-only scheduler：研究、复盘、执行三类 Run 的统一调度
- Runtime watchdog：周期心跳、最长执行时间、卡死识别和维护态切换
- Context freshness：宏观、行情、组合风险分别计算年龄和可信状态
- Architecture contract：扫描活动源码和构建产物，禁止旧控制器标识重新出现

## 6. 修复本次高风险误报

旧控制器删除不能代替风险数据修复。本次切换同时完成：

1. 宏观采集从全市场 K 线重任务中解耦，单独刷新和记录心跳；
2. 宏观快照增加可配置 TTL、原始时间、采集时间、来源和 stale/error 状态；
3. 过期宏观数据的风险等级显示为“未知/数据过期”，不得继续冒充实时“高”；
4. 为安全起见，数据过期时仍可阻止新增仓位，但原因必须是“宏观数据过期”，不能是历史 WTI 波动；
5. 综合风险的新鲜度必须覆盖宏观、组合、调度器和 Agent 决策，不再只检查账户与组合风险接口；
6. watchdog 发现周期超过上限时使系统进入维护态，并暴露中文告警，而不是仅凭 PID 显示“运行中”。

## 7. 测试策略

按测试驱动实施，先写失败测试，再删除或迁移代码：

1. 架构扫描测试：活动代码、配置、API、UI、构建产物中不存在旧控制器标识。
2. 调度器测试：所有模式只调度 Agent；Agent 失败只进入失败关闭。
3. 权限测试：非 Agent actor/source 无法取得执行 grant 或 session。
4. 决策读取测试：只接受绑定 Run、验证器、发布凭证和执行会话的 Agent 决策。
5. 模拟盘闭环测试：Agent -> 风控 -> 订单 -> 账本全链路有效，研究/复盘 Run 零订单。
6. 风险时效测试：过期宏观数据不显示高风险，但精确阻止新增仓位。
7. 卡死测试：超时周期被识别，维护态可见，不能继续使用旧决策。
8. API/UI 契约测试：只显示 Agent 管控、维护态和中文阻断原因。
9. 全量回归与实际启动验收。

## 8. 迁移顺序

1. 建立 Agent-only 失败测试和架构扫描测试。
2. 停止并隔离旧调度周期，完成活动状态对账。
3. 收拢通用分析能力到 Agent 模块。
4. 删除旧循环及其所有调用者。
5. 收紧 authority、session、decision reader 和 paper trader。
6. 改造调度器为 Agent-only，并加入 watchdog。
7. 修复宏观采集解耦、TTL 和综合风险时效。
8. 删除旧 API/UI 控制面和过时文档，重建 `dist`。
9. 迁移活动数据库状态并启动 Agent。
10. 完成定向、全量、构建、冒烟、真实请求和运行时唯一所有者验收。

## 9. 非目标

- 不开放实盘或券商自动交易。
- 不让 LLM 覆盖确定性硬风控。
- 不借本次切换重写无关的数据、Qlib 或前端模块。
- 不删除或伪造真实交易、订单、风险和审计事实。
