# F5 盘中自动模拟交易设计

## 1. 目标

让已通过 F5 实验准入的上一完整交易日研究组合，在下一交易日的盘中窗口自动生成目标差额订单、使用逐股实时行情即时模拟成交，并在同一事务链中更新现金、持仓、权益和十项对账。该能力仅属于本地模拟盘，`live_execution_authority` 永久为 `false`。

## 2. 当前问题与根因

现有 F5 只实现日频次日开盘模型：`service._prepare()` 固定调用 `next_session()`，`eligibility` 要求组合日期等于运行日期，`simulator` 只读取完整日线 `open`。因此交易时间运行时，上一交易日完整组合被判过期或被安排到再下一个交易日，实时行情虽然存在却不参与撮合。

## 3. 方案选择

采用独立的 `paper_intraday` 通道，不修改原 `paper_daily` 语义：

- 日频通道继续承担历史兼容和收盘后兜底。
- 盘中通道使用上一完整 research generation，目标交易日为当前交易日。
- 盘中脚本主动刷新组合内全部证券的实时行情，不依赖 200 只轮询列表是否恰好覆盖组合。
- 盘中成交使用实时 `price` 加既有滑点、费用、参与率、T+1、涨跌停和停牌规则，不把实时价伪装为开盘价。
- 账本沿用 schema v3；运行键由组合、当前交易日和政策哈希唯一确定，同一组合当日重复触发只返回既有结果。

不采用直接复用日线 `open`，因为那会伪造成交时点；不采用在 Web 请求中隐式触发，因为页面访问不能拥有调度权。

## 4. 数据与时间门禁

盘中一次运行必须同时满足：

1. 本地时间为周一至周五，且位于 `09:35-11:25` 或 `13:05-14:50`。
2. selection/factor 来自同一完整 generation，日期早于当前交易日且为当前可用的最近完整研究日。
3. F4、候选锁、policy hash、数据版本和实验准入规则继续全部通过。
4. 组合内每只证券主动获取到实时行情；行情时间属于当前交易日，年龄不超过 120 秒。
5. 价格、累计成交量有限且为正；停牌、涨跌停和容量规则继续生效。

任一条件失败只记录明确阻断原因，不生成订单或成交。

## 5. 执行流程

```text
Windows 计划任务（工作日每 5 分钟）
  -> f5_paper_intraday.py --once
  -> 交易时段门禁
  -> 单次解析完整 research generation + 实验组合
  -> 主动刷新组合内逐股实时行情
  -> F5 双通道 eligibility（expected_selection_date=完整研究日）
  -> 当前模拟账户与实时价计算目标差额
  -> 实时价模拟成交
  -> 原子写订单/成交/现金/持仓/权益
  -> 十项对账
  -> completed / completed_with_rejections / halted_unknown
```

## 6. 调度

新增 `XuanJiQuant-Paper-Intraday`：工作日 09:35 启动，每 5 分钟重复到 14:50，`IgnoreNew`。脚本内部再次执行上午、下午交易窗口门禁，因此午休和收盘后触发只返回 `outside_intraday_window`。原 `XuanJiQuant-Paper-Daily` 16:40 任务保留。

## 7. API 与页面

`/api/paper-execution` 新增无参数 `run_intraday` 控制动作；仍禁止传入证券、方向、数量和价格。状态投影增加当前执行模式、行情时间和盘中阻断原因。页面显示“盘中实验模拟”，不得显示为实盘成交。

## 8. 完成判定

- 当前实验组合 5 只证券均以主动刷新行情通过新鲜度门禁。
- 交易窗口内一次运行生成唯一 run，并完成订单、成交、持仓、权益和对账；重复运行无重复副作用。
- 过期行情、午休、涨跌停、停牌、缺行情、F4 安全失败均无成交。
- `live_execution_authority=false`，任意订单接口继续返回 `arbitrary_order_action_forbidden`。
- Python、Node 契约、TypeScript、Vite、Web/UI 验证通过。
