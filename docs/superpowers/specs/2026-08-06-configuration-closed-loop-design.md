# 配置闭环与硬风控一致性设计

## 目标

确保每个可编辑设置都满足“页面输入、服务端保存、运行时读取、实际执行、页面回显”五层一致。首要验收项是：驾驶舱把“单只股票上限”保存为 20% 后，Agent 组合计划、调度器、风险指标和订单网关都必须使用 `0.20`，不得再出现 Agent 计划为 80%、订单网关为 20% 的分裂状态。

## 已确认的故障

1. `ai:autonomous:config.risk.max_position_pct` 为 `0.8`，而 `ai:scheduler:config`、`paper:config` 和最终 `load_risk_config()` 为 `0.2`。
2. 最新 Agent 计划把 `risk_budget.max_position_pct` 写成 `0.8`，并生成 `0.25` 的目标权重；最终订单网关另行按 `0.2` 拦截。
3. `save_autonomous_config()` 只把启用状态和模型同步到调度配置，没有同步风险、目标、执行参数，旧调度快照可以覆盖新配置。
4. `load_risk_config()` 采用简单覆盖顺序；带有完整默认风险副本的 `paper:config` 可以覆盖驾驶舱刚保存的更严格限制。
5. 驾驶舱保存后丢弃服务端返回的规范化配置，定时刷新又使用 `current || serverConfig`，本地旧值不会被纠正。
6. 保存配置会把 `enabled` 同步给调度器，与页面“保存不会自动启动”的承诺冲突。

## 方案比较

### 方案 A：只修 Agent 规划器

让规划器读取 `load_risk_config()`。改动最小，但三份配置仍会漂移，页面回显和调度热加载仍不可靠，不采用。

### 方案 B：统一权威解析并保留现有模块边界（采用）

- `ai:autonomous:config` 保存驾驶舱的全局业务配置。
- `ai:scheduler:config` 保留进程生命周期字段，同时同步完整业务配置，避免旧快照覆盖。
- `paper:config.risk` 只能进一步收紧全局风险，不能放宽；文件 `quant/risk/hard_limits.json` 仍是不可绕过上限。
- Agent 规划、风险指标、预交易和执行统一调用 `load_risk_config()`。
- UI 保存后使用服务端回执覆盖本地状态，并显示已保存值与实际生效值。

该方案不删除现有缓存键，不重写调度器或执行器，兼容面最小。

### 方案 C：新建独立配置服务并迁移全部缓存键

长期最整洁，但会同时改动 API、缓存、调度、Agent、模拟盘和测试，当前修复风险过大，不采用。

## 权威数据流

```text
驾驶舱输入 20%
  -> API 接收 0.20
  -> save_autonomous_config 规范化并保存
  -> 同步调度业务快照，但保留进程 enabled 状态
  -> load_risk_config 合并全局设置与仅可收紧的模拟盘限制
  -> hard_limits.json 再施加不可绕过上限
  -> Agent 计划 / 风险指标 / 预交易 / 执行网关读取同一结果
  -> API 回执返回 configured + effective
  -> 页面回填并显示 20%
```

## 配置边界

- 最大类限制（单票、总暴露、持仓数、订单数、换手、亏损、回撤）：下游覆盖只能取更严格的较小值。
- 最小现金缓冲：下游覆盖只能取更严格的较大值。
- `kill_switch`：任一层开启即开启。
- 放宽类布尔项（买 ST、买涨停、卖跌停）：所有层都允许时才允许。
- `capital_cap`：零表示未设置；多个非零值取较小值。
- 保存动作不改变调度器运行状态；启动和停止动作是唯一生命周期入口。
- 超过单票限制的新增买单必须拒绝；既有超限仓位由目标组合生成减仓量，不以保存配置为触发器直接静默下单。

## 全功能排查范围

1. 驾驶舱 9 个编辑项：目标权益、周期、供应商、模型、深度推理、4 个硬风险限制。
2. 策略页模拟盘配置：策略、参数、选股池、仓位比例、持仓数、执行时间、LLM 开关/继承/供应商/模型/模式。
3. 运行控制：保存、启动、停止、单次运行、Agent 维护/启用边界。
4. 数据同步和 Tick 采集器的启动/停止/状态回显。
5. 所有现有 Python、Node、TypeScript、Vite、Web 和 UI 验证脚本作为跨功能回归门禁。

## 错误处理与审计

- 非数字、无穷值、越界百分比和非法持仓数在服务端规范化或拒绝，不能只依赖 HTML `min/max`。
- API 成功必须返回规范化后的持久化配置和实际风险；UI 不得用提交前对象假装保存成功。
- 配置漂移被检测到时返回明确中文状态，不把执行网关的最终拦截伪装成 Agent 已正确理解配置。

## 测试设计

- 先写失败测试，证明 20% 被旧调度/模拟盘副本覆盖、Agent 仍读取 80%、保存会改动生命周期、UI 不回填回执。
- 修复后验证 `configured=0.20`、`planner=0.20`、`gateway=0.20`。
- 用纯函数/内存缓存验证 19% 买入允许、21% 买入拒绝，避免产生真实或模拟委托。
- 最后恢复服务，通过真实 API 保存与读取 20%，再执行浏览器交互和全量回归。
