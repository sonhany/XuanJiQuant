# XuanJiQuant 数据层主权与五层解耦设计

## 1. 目标

本设计把 XuanJiQuant 收敛为一个可验证的五层量化系统，第一阶段只治理数据层及其边界，不继续在 Agent、因子、策略、风控和执行内部零散打补丁。

核心原则只有一条：**数据层是市场数据唯一写入者，其他层只能读取已发布的数据产品。**

项目继续保持 `paper-only`。本设计不接入实盘，不降低风控阈值，不绕过 verifier、执行会话、幂等键、硬风控或审计账本，也不删除现有历史数据。

## 2. 当前问题与证据

### 2.1 写权限散落

当前至少存在以下越层写入或隐式采集入口：

- `ai_tools.json` 把 `refresh_data` 注册为 `auto_allowed=true`，并允许 Agent 在 `observe/research/shadow/paper_guarded` 模式调用。
- `scripts/ai_action_executor.py:355-368` 允许 Agent 直接执行 `sync_universe()` 和 `incremental_klines()`。
- `scripts/paper_trader.py:697-706` 在交易流程发现日线过期时自行补数并重新加载。
- `scripts/ai_data_agent.py:125-167` 可以直接补 K 线和财务数据；`server/routes/paper.mjs:450-464` 又向页面开放 `auto_fix`。
- `server/routes/paper.mjs:645-675` 的旧“五层一键运行”把数据、因子、策略、执行建议和风险混成一个串行入口。
- `quant/data/sync_service.py:45,193-203` 从数据采集服务反向调用 Agent 实时处理路径，使数据层依赖控制层。
- `scripts/data_runner.py` 的部分读取动作会直接请求外部行情并写展示缓存；`quant/valuation/data.py` 的估值补历史链还可能扩展共享日 K。

结果是同一轮因子、策略和 Agent 可能看到不同时间、不同覆盖范围的数据，且无法用一个版本号说明本轮依据。

### 2.2 状态来源冲突

2026-08-13 本轮只读快照显示：

- `data/quant.db` 的 `PRAGMA quick_check` 为 `ok`，文件约 895,963,136 字节。
- 当前股票全集 5,203 只，日 K 键 5,205 个；其中 5,201 个键末条日期为 `20260812`，4 个键仍停在更早日期。
- 实时报价键 206 个，财务摘要键 5,205 个，财务交叉核验键 5,203 个，tick 15,224 行，盘口 87 行。
- `data:health:last.checked_at` 为 `2026-08-13T13:49:19`，其最新日线日期为 `20260812`。
- 旧 `ai:data:latest` 却生成于 `2026-08-03 17:43:21`，只抽查 50 只并声称当时不陈旧。
- Web/API `127.0.0.1:8880` 本轮请求无法连接，因此持久化的 daemon `running=true` 只能视为历史状态，不能证明当前服务存活。

这说明 `ai:data:latest` 不能继续作为数据质量事实，进程状态、数据覆盖、数据版本和 AI 解读也不能混为一个对象。

## 3. 推荐总体架构

```text
外部市场源
  -> 数据源适配器
  -> 原始响应与来源回执
  -> 标准化/去重/交易日/生命周期处理
  -> 数据质量门禁
  -> 版本化数据发布
       -> 因子层（只读）
       -> 策略层（只读）
       -> 风控层（只读）
       -> 执行层（只读行情 + 自有交易账本）
       -> Agent（只读证据 + 编排，不得补数）
       -> 页面（只读展示）
```

任何下游层发现数据过期时只能返回 `data_not_ready` 并失败关闭。它不能调用数据源、写市场事实、修改发布时间或把缓存值重新盖章为实时值。

## 4. 数据层职责

### 4.1 数据层拥有

- 数据源选择、限频、超时、熔断、重试和来源健康。
- 股票全集、上市/退市生命周期和交易日历。
- 日 K、分钟线、实时行情、tick、盘口、财务、资金流、指数、宏观和公告的采集与标准化。
- 去重、排序、字段校验、跨源核验、异常隔离、覆盖率和新鲜度判断。
- 数据任务调度、任务账本、快照发布、版本号、哈希、来源和审计回执。
- 对外只读查询和显式的数据管理控制面。

### 4.2 数据层不拥有

- 因子公式、因子评分、策略信号、目标组合、风险许可和订单。
- Agent 计划、模型解释、交易政策、执行权限或模拟成交。
- Qlib 模型训练、Recorder、候选晋升和交易执行。

## 5. 数据源重新整合

目标策略按数据类型固定，不允许调用方自行换源：

| 数据产品 | 目标主源 | 交叉核验/降级源 | 发布频率 | 备注 |
|---|---|---|---|---|
| A 股股票全集与名称 | AkShare | TdxQuant 证券列表核验 | 每交易日盘前一次 | 保留退市历史，不伪造上市前数据 |
| 实时报价 Level-1 | TdxQuant | 新浪、腾讯 | 盘中固定周期 | 只发布监控集覆盖，不宣称全市场实时 |
| 分钟线/盘中 OHLCV | TdxQuant | 腾讯 | 盘中固定周期 | 未闭合 bar 不进入日线 |
| 日 K | TdxQuant | 腾讯交叉核验；新浪/Baostock 降级 | 收盘结算窗口后一次 | 先暂存，质量通过后原子发布 |
| tick/盘口 | TdxQuant/tdxrs 适配器 | 无可靠降级时明确缺失 | 仅授权监控集 | 不用快照伪造逐笔成交 |
| 财务报表 | AkShare | 可用时由 Tushare 交叉核验 | 盘后确定性批次 | 必须保留报告期和公告时点 |
| 个股资金流/板块资金流 | 东方财富 | 无可靠降级时明确缺失 | 盘中/盘后固定周期 | 缺失不能填零 |
| 指数/基准 | TdxQuant | 腾讯 | 盘中及收盘 | 与个股代码命名空间隔离 |
| 宏观、快讯、财经日历 | Jin10 MCP | 缓存仅作 stale 展示 | 固定周期 | 宏观数据不直接写交易许可 |
| 公告 | 巨潮资讯 | 无 | 固定轮询 | 保存公告时间、类型和原文标识 |

`quant/data/source_policy.py` 是目标策略登记入口，但只有被采集器实际使用并产生来源回执的策略才算生效。配置声明本身不能证明数据来自该源。

## 6. 三类存储与事实边界

### 6.1 在线市场数据

P0 保留现有 `data/quant.db`，避免大爆炸迁移，但通过代码所有权限制只有数据层模块可写市场数据命名空间。实时 TTL、日 K、财务和展示缓存必须使用不同命名空间。

P1 新增独立的数据目录和元数据索引，用于不可变发布清单、任务记录和来源回执。是否把大体量历史行情迁入 Parquet/ClickHouse，在完成双读校验后单独决定；不得先写“ClickHouse 已接入”。

### 6.2 交易与审计事实

订单、成交、持仓、现金、风险事件、Agent Run、执行会话和审计事实仍在交易账本中，由各自确定性模块拥有。数据层不得修改这些事实。

### 6.3 Qlib 研究事实

`data/qlib`、`qlib_meta.db`、Recorder/MLflow 和研究产物继续独立。Qlib collector 可以复用已验证的数据源适配算法，但不得写在线市场缓存；在线数据层也不得把 Qlib 注册表冒充实时市场数据。

## 7. 版本化发布合同

每次成功发布必须产生一个 `data_snapshot`，至少包含：

- `snapshot_id`：不可重复版本标识；
- `dataset`：如 `a_share_daily`、`realtime_watch`、`fundamentals`；
- `as_of`：数据业务时点；
- `published_at`：发布时间；
- `universe_version` 和股票生命周期版本；
- `expected_count`、`available_count`、`coverage`；
- `source_chain` 和各源结果；
- `content_hash` 或成员哈希清单；
- `quality_status`：`passed/partial/failed`；
- `freshness_status`：`fresh/stale/unknown`；
- `failure_reasons`；
- `execution_authority=false`。

只有 `quality_status=passed` 的快照才能成为因子和策略的默认输入。`partial` 可供页面展示或研究诊断，但不能冒充完整全市场数据。失败发布不能覆盖最后一个已通过版本。

## 8. 五层权限矩阵

| 层 | 可读 | 可写 | 明确禁止 |
|---|---|---|---|
| 数据层 | 外部数据源、数据任务配置 | 市场数据、质量、发布清单、来源回执 | 因子、策略、风险许可、订单和成交 |
| 因子层 | 已通过的数据快照、因子元数据 | 因子快照、IC/IR、候选研究证据 | 外部采集、补数、订单 |
| 策略层 | 数据快照、因子快照、研究门禁产物 | 信号、目标组合候选、回测证据 | 修改市场数据、直接下单 |
| 风控层 | 市场快照、持仓/现金/订单事实、风险配置 | 风险指标、逐单许可、风险事件 | 补数、改策略、改订单事实 |
| 执行层 | 已验证 Agent 决策、风险许可、实时行情、交易账本 | 模拟订单/成交/持仓/现金/对账 | 补历史数据、训练因子/策略、绕过门禁 |
| Agent | 上述各层发布的只读证据 | Run、计划、解释、工具回执和受控编排事实 | 数据采集/补数、改硬风控、直接写订单/成交/持仓/现金 |
| 页面 | 各层只读投影 | 显式人工配置或数据管理请求 | 隐式刷新并改写事实 |

## 9. 确定性调度

数据更新只由数据层调度器决定：

- 盘前：股票全集、交易日历和基础状态核对；
- 盘中：实时报价、监控集分钟线、必要的资金流和指数；
- 收盘结算窗口后：全市场日 K 补齐、跨源核验、质量门禁和原子发布；
- 盘后：财务、公告、数据健康和差异报告；
- 周期性离线：Qlib 自有采集、质量、训练和研究发布。

Agent、因子、策略、风险和执行层均不得触发上述任务。人工需要立即更新时，只能通过数据管理控制面显式提交，记录操作者、原因、范围和幂等键。创建或修改 Windows 计划任务属于外部运行状态变更，实施时必须单独确认后执行。

## 10. P0 止血范围

第一阶段只做以下最小但决定性的变更：

1. 从 Agent 工具清单移除 `refresh_data` 及 `run_daily_update` 别名；Agent 上下文不再出现任何数据写工具。
2. 删除 `scripts/ai_action_executor.py` 中 Agent 直调 `sync_universe/incremental_klines` 的分支。
3. 模拟交易发现数据过期时只返回 `data_not_ready`，删除 `scripts/paper_trader.py` 的自动补数路径。
4. 删除旧 `ai_data_agent` 的补数权限和 `server/routes/paper.mjs` 的 `auto_fix`/“五层一键运行”入口；数据质量改读数据层发布状态。
5. 删除 `quant/data/sync_service.py -> quant.agent.realtime` 的反向依赖；Agent 自行只读消费已发布报价快照。
6. 增加架构契约测试，禁止 `quant/agent`、因子、策略、风险和执行模块导入数据采集写入口。
7. 保留现有数据管理页面的显式人工更新，但把读请求与写任务分开，并记录审计。

P0 不迁移数据库、不重写全部数据适配器、不删除历史 K 线、不改变硬风控，也不启动真实交易。

## 11. P1/P2 后续迁移

### P1：数据产品化

- 建立数据任务账本、发布清单和稳定的 `DataSnapshotReader`。
- 因子、策略、风控、执行和 Agent 全部改为携带 `snapshot_id/as_of`。
- 页面分别展示数据业务时点、发布时间、覆盖率、来源和服务存活，禁止一个“正常”覆盖全部状态。
- 估值长历史、市场浏览和实时查询不得回写已发布日线；需要入库时提交独立数据任务。

### P2：物理隔离和容量治理

- 在双读、哈希和回放验收通过后，再评估把历史数据迁到 Parquet 或 ClickHouse。
- `quant.db` 逐步只保留在线状态、交易账本和兼容投影；不得无验证地一次性搬库。
- 建立备份、恢复、数据血缘、保留期和容量阈值。

## 12. 失败处理

- 主源失败：按固定策略尝试核验/降级源，记录每次响应；不由调用方临时选择。
- 覆盖不足：发布 `partial/failed`，保留上一通过版本，但明确其已过期。
- 数据冲突：隔离冲突股票或字段，生成差异报告；不能静默覆盖。
- 数据过期：下游失败关闭，不自行补数，不沿用旧候选冒充当前决策。
- 数据服务不可用：状态为 `unavailable`，持久化 `running=true` 不作为存活证据。
- Qlib 数据不完整：研究任务失败关闭，不影响在线数据层，也不能直接晋升交易。

## 13. 测试与验收

### P0 必须验证

- Agent 工具注册表不含数据写工具或其别名。
- Agent 运行、模拟交易、因子、策略、风控、执行源码不存在对 `daily_update` 写函数的直接调用。
- 数据同步服务不导入 Agent 模块。
- 数据过期时模拟交易明确跳过且不发生任何网络采集或市场数据写入。
- 旧 `ai:data:latest` 不再决定当前数据质量；当前质量来自数据层确定性覆盖计算或发布清单。
- 数据管理人工更新仍可审计、幂等、互斥，且不由普通读请求隐式触发。

### 回归范围

- 数据层、Agent、模拟执行、因子、策略、风险相关 Python 测试；
- 全部 Node 契约；
- TypeScript、Vite 构建、Web/UI 验证；
- 浏览器控制台；
- SQLite `quick_check` 和只读覆盖核对；
- README、`docs/XUANJI_HANDOFF.md` 和系统全景图同步。

## 14. 完成判定

只有以下条件全部成立，才可宣称“数据层独立化 P0 完成”：

1. 数据市场事实只有数据层写入口；
2. Agent、模拟交易和研究层不能补数；
3. 下游每次计算可指出数据业务时点和覆盖口径；
4. 数据过期能稳定失败关闭而不是触发跨层写入；
5. 相关及全量回归通过；
6. 文档和全景图与源码一致；
7. 未把缓存、持久状态、历史 AI 结论或部分覆盖冒充当前完整数据。

## 15. 非目标

- 本阶段不新增数据源，不追求 100% 全市场 tick，不接入实盘接口。
- 不让 AI 选择数据源、修复数据或调整调度。
- 不把 Qlib、因子、策略和交易账本合并为一个数据库。
- 不因清理架构而删除可审计的历史数据、订单、成交或 Agent 轨迹。
- 不使用“服务能启动”替代数据质量、来源和覆盖验收。
